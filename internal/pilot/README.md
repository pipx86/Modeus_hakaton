# pilot: аудит данных пилота

Пакет проверяет, хватает ли данных для пилота, и ничего не меняет в базе:

- **карточка 4** — источники по пилотной профессии;
- **карточка 5** — структурированные данные выбранной образовательной программы.

Аудит работает в трёх режимах:

- **PostgreSQL** — штатный режим на стенде (`DATABASE_URL` или `-dsn`);
- **JSON-снимок** (`-dataset path`) — офлайн-проверка заранее сохранённых данных;
- **встроенная фикстура** (`-fixture`) — демонстрационный набор для проверки самой
  команды и CI без базы.

В режимах `-dataset` и `-fixture` PostgreSQL не нужен, `DATABASE_URL` не читается.

## Быстрый старт без PostgreSQL

```powershell
go run ./cmd/pilot-audit -profession "Аналитик данных" -fixture
go run ./cmd/pilot-audit -fixture -program program-data-analyst
go run ./cmd/pilot-audit -profession "Аналитик данных" -fixture -strict
```

Фикстура — вымышленный набор: 6 источников четырёх типов, одна программа,
3 компетенции, 5 KSA и 3 связи с таксономией. Оба отчёта печатают
`Статус: готово`, команда возвращает 0. Это проверка формата и правил аудита,
а не данные пилота.

Примеры снимков для ручного запуска лежат в репозитории:

```powershell
go run ./cmd/pilot-audit -dataset testdata/pilot/sources-sample.json -profession "Аналитик данных"
go run ./cmd/pilot-audit -dataset testdata/pilot/program-sample.json -program program-data-analyst-2026
```

## Режим PostgreSQL

```powershell
$env:DATABASE_URL = "postgres://postgres:postgres@localhost:5432/activity?sslmode=disable"

go run ./cmd/pilot-audit -profession "аналитик данных"
go run ./cmd/pilot-audit -program <uuid программы>
go run ./cmd/pilot-audit -profession "аналитик данных" -program <uuid> -json
```

DSN берётся из `-dsn` или `DATABASE_URL`. В режиме базы ID программы обязан быть
UUID; в снимке и фикстуре допускается любая непустая строка.

## Флаги

| Флаг | Смысл |
| --- | --- |
| `-profession` | Профессия для аудита источников. Нужна хотя бы одна цель: `-profession` и/или `-program`. |
| `-program` | ID образовательной программы. В базе — UUID, в офлайн-снимке — строка из снимка. |
| `-dsn` | Строка подключения PostgreSQL; по умолчанию `DATABASE_URL`. Только для режима базы. |
| `-dataset` | Путь к JSON-снимку данных. Исключает `-fixture` и не требует базы. |
| `-fixture` | Встроенный демонстрационный набор. Исключает `-dataset` и не требует базы. |
| `-json` | Вывести отчёт объектом `sources` / `program` вместо текста. |
| `-strict` | Вернуть код 1, если хотя бы один отчёт имеет статус «требует внимания». |

Коды возврата:

| Код | Значение |
| --- | --- |
| `0` | Отчёт построен. Статус может быть «готово» или «требует внимания» |
| `1` | Статус «требует внимания» при включённом `-strict` |
| `2` | Ошибка конфигурации, чтения снимка или недоступная база |

Пример для CI:

```powershell
go run ./cmd/pilot-audit -dataset testdata/pilot/sources-sample.json -profession "Аналитик данных" -strict
```

## Снимок данных (`-dataset`)

Снимок — один JSON-файл с уже выбранными данными. Секции повторяют то, что
`Store` читает из базы:

```json
{
  "sources": [
    {
      "id": "src-hh-vacancy-da-001",
      "type": "vacancy",
      "title": "Аналитик данных — вакансия hh",
      "content": "Требования: SQL, хранилище данных, дашборды.",
      "source_url": "https://hh.example/vacancy/da-001",
      "created_at": "2026-11-10T09:00:00Z",
      "published_at": "2026-11-01T08:00:00Z"
    }
  ],
  "analyzer_matches": ["src-hh-vacancy-da-001"],
  "program": {
    "id": "program-data-analyst-2026",
    "title": "Прикладная аналитика данных",
    "has_learning_outcomes": false,
    "has_disciplines": false
  },
  "competencies": [{"id": "comp-sql", "code": "SQL", "title": "SQL и хранилище"}],
  "ksa": [{"id": "ksa-sql-queries", "competency_id": "comp-sql", "kind": "skill", "title": "Писать SQL-запросы"}],
  "taxonomy_links": [{"competency_id": "comp-sql", "taxonomy_item_id": "taxonomy.sql"}]
}
```

Правила загрузки:

- неизвестные поля, синтаксическая ошибка и данные после JSON — ошибка (код 2);
- UTF-8 BOM в начале файла допускается: его добавляют некоторые Windows-редакторы;
- пустой снимок допустим: это честный ответ «данных нет», аудит вернёт «требует внимания»;
- `sources` — снимок уже отфильтрован по профессии, повторная фильтрация по названию не выполняется;
- `analyzer_matches` — какие источники нашёл анализатор вакансий на момент снятия снимка. Если поле пустое, отчёт честно покажет `найдено анализатором: 0`;
- ID источников, компетенций и KSA непустые и уникальные;
- `program` обязательна, если есть `competencies`, `ksa` или `taxonomy_links`;
- у `taxonomy_links` заполнено ровно одно из полей `competency_id` / `ksa_id`, ссылка ведёт на существующий элемент, `taxonomy_item_id` непустой;
- `kind` у KSA, если указан, — `knowledge`, `skill` или `ability`.

Файлы `testdata/pilot/sources-sample.json` и
`testdata/pilot/program-sample.json` — реалистичные примеры: первый содержит
только источники, второй — программу с компетенциями, KSA и связями.

## Как читать статусы

`Статус: готово` — выполнены правила готовности. `Статус: требует внимания` —
хотя бы одно правило не выполнено; конкретные причины перечислены в разделе
«Проблемы». Проблемы могут быть и у готового набора: например, отсутствие
совпадений с анализатором или отсутствие структурных дисциплин не блокируют MVP.

### Источники

Готово, если одновременно:

- всего не меньше 5 источников;
- не меньше 3 разных типов;
- есть хотя бы один источник одновременно с непустым текстом и URL.

В строке типа: `всего / с текстом / с URL / с датой / пригодных`. «Пригодный» — с
текстом и URL; дата учитывается отдельно. «С датой» — заполнен `created_at` или
`published_at`. `Анализатор` — в режиме базы это существующий адаптер вакансий hh
(`store.NewVacancyAdapter`); в офлайн-режиме — список `analyzer_matches` из снимка.

### Программа

Готово, если одновременно:

- программа найдена по ID;
- не меньше 3 компетенций;
- не меньше 5 KSA;
- есть хотя бы одна связь компетенции или KSA с таксономией.

Дисциплины и результаты обучения в текущей схеме не структурированы:
соответствующих таблиц нет, поэтому отчёт честно пишет «только в документах».
Это ограничение MVP, а не ошибка программы.

## Ручной эталон пилота (карточка 27)

**Пилотный эталон пока не заполнен: пилот не выбран.** В репозитории нет
согласованного дерева и цитат для конкретной профессии, и этот README их не
выдумывает. Эталон заполняет методист вместе с экспертом по формату
[`internal/agent/eval/testdata/reference/README.md`](../agent/eval/testdata/reference/README.md);
`data-analyst.json` там — только демонстрация формата, а не эталон пилота.

Когда эталон согласован, он подключается к eval одной командой:

```powershell
go run ./cmd/agent-eval -reference internal/agent/eval/testdata/reference/<профессия>.json -case <кейс> -enforce-thresholds
```

Команда прогоняет офлайн-кейсы, сравнивает дерево указанного кейса с эталоном и
возвращает 1, если `recall < 0.80` или есть `level_mismatch`. Без
`-enforce-thresholds` отчёт печатается, но код возврата остаётся прежним.
Машиночитаемый отчёт по эталону — `-report json`.

Пример на демонстрационном эталоне (ожидаемо даёт recall 0.50, потому что
пример не совпадает с baseline):

```powershell
go run ./cmd/agent-eval -reference internal/agent/eval/testdata/reference/data-analyst.json -case data-analyst-baseline
```

По умолчанию сравнивается дерево последнего кейса, поэтому `-case` лучше
указывать явно.

## Ограничения

- Аудит не заменяет проверку смысла источников и не проверяет дубли, права и обезличивание.
- Поиск по профессии в базе — `ILIKE` по отдельным словам с приоритетом источников, где совпало больше слов; это эвристика, а не семантический поиск. Снимок считается уже отфильтрованным.
- В офлайн-режиме анализатор вакансий не запускается: `analyzer_matches` — это зафиксированный в снимке результат, а не живой поиск.
- Отдельной даты материала схема не хранит: `Dated` опирается на дату импорта и дату публикации вакансии.
- Наличие дисциплин и результатов обучения определяется только по именам таблиц, а не по строкам конкретной программы.
- Фикстура демонстрационная: её нельзя использовать как данные пилота или как эталон.

## Тесты

```powershell
go test ./internal/pilot/ ./cmd/pilot-audit/ ./internal/agent/eval/ ./cmd/agent-eval/
```

Тесты `internal/pilot` работают с чистыми функциями, снимками и фикстурой; тесты
`internal/agent/eval` запускают пайплайн на скриптованном офлайн-клиенте.
PostgreSQL не нужен ни тем, ни другим.
