# Проверка извлечения ЗУН — 21 ноября 2026

**Результат:** два независимых синтетических контроля прошли; один preview на существующем backend-дереве завершился без ошибок. Это подтверждает исправление проверенных сценариев, но не заменяет оценку на выборке реальных исследований. Результаты не отправлялись в Git и не сохранялись в словарь исследования.

## Что проверялось

- Продуктовый `POST /api/v1/runs/{id}/skill-model/extract` через локальный API и настроенную LLM `minimax-m3.1-flash` на `api.reformboss.com`.
- Одно существующее локальное backend-дерево: 20 узлов и их цитаты. Пользователь отдельно разрешил эту передачу. Происхождение материала и участие реального специалиста не подтверждались, поэтому это не считается пилотным исследованием.
- Десять синтетических случаев: перечень технологий без описания применения; знание без практики; совместная задача backend на Python и PostgreSQL; задача архитектора без Python; явно подтверждённое владение; неполное описание SQL-задачи; требование вакансии; протоколы и подходы рядом с реальными инструментами; отклонённая цитата; prompt injection в документе.

Ответы были только предварительным просмотром. После проверки словарь остался на ревизии `0` с нулём сохранённых связей. JSON исходного дерева из 20 узлов до и после проверки совпал полностью. Искусственные исследования и источники удалены скриптом; результаты вызовов LLM хранятся только в игнорируемом `.secrets/skill-quality/`.

## Что исправлено

1. В запрос LLM добавлен тип каждого источника. Модель различает вакансию, интервью, стандарт и документ; требование вакансии получает `basis=requirement`.
2. Уточнено, что инструментом считается конкретная программная технология: язык, СУБД, фреймворк, библиотека, платформа, приложение или CLI. REST, GraphQL, OpenAPI, JWT, OAuth2, RBAC и scopes не предлагаются как инструменты. Упоминание Pull Request не позволяет выводить GitHub/GitLab или назначать Git для отправки PR.
3. Новая ссылка на версию ЗУН исправляется только когда для того же ID в ответе есть единственная версия. Неизвестные ID и неоднозначные версии по-прежнему отклоняются.
4. Повтор одного и того же ID цитаты внутри связи удаляется. Модель отдельно инструктируется ссылаться на цитаты только того узла, к которому они прикреплены; сервер проверяет принадлежность.
5. Кандидат «владение» с незаполненными полями действия, объекта, условий, результата, критерия, самостоятельности или диапазона ситуаций понижается до «умения». Уже сохранённые определения этот проход не меняет.
6. Правила формата JSON, сохранения существующего справочника, исключения отклонённых цитат, обязательного ручного подтверждения и запрета выдуманных версий инструментов сохранены.

Ни одно предложение не было подтверждено автоматически. Владение не выведено: в этом материале не хватало полного набора явных оснований для более сильной категории. Проверку сохранности прошли исходное дерево, словарь и история.

- в backend-примере связаны Python и PostgreSQL, а в задаче архитектора Python не появился из отрицания;
- требование вакансии не выдано за опыт человека и связано с `basis=requirement`;
- явно описанное владение сохранило критерий, самостоятельность и диапазон ситуаций;
- REST/GraphQL и стандарты авторизации не попали в справочник инструментов;
- Git связан с созданием ветки, а не с Pull Request;
- выдуманные версии технологий, отклонённая цитата и инструкция внутри документа не прошли контроль.

## Границы вывода

Проверены десять искусственных формулировок и один набор материалов. Это не даёт статистической оценки точности на профессиях или реальных интервью. Один успешный preview не доказывает полноту извлечения или семантическую эквивалентность названий. Источник существующего исследования отдельно не проверялся на принадлежность реальному пилоту. Ответы LLM не записывались в исследование. Изменения остаются локальными, push не выполнялся.

## Как повторить синтетическую проверку

Два сохранённых локальных ответа можно проверить так:

```powershell
python scripts/evaluate_skill_extraction.py .secrets/skill-quality/controls-final-1.json .secrets/skill-quality/controls-final-2.json
```

Ожидаемый код завершения — `0`; проверяющий скрипт оценивает только перечисленные контрольные случаи и не заменяет ручную экспертизу.

Точечные регрессионные тесты:

```powershell
go test ./internal/api ./internal/domain/... -count=1
```
