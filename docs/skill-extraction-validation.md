# Проверка извлечения ЗУН на нескольких исследованиях — 21 ноября 2026

**Результат:** два preview на разных завершённых backend-исследованиях вернули HTTP 200. Два независимых прогона десяти синтетических случаев прошли все 21 контрольное условие. Это полезная повторная проверка, но не методический пилот: оба дерева имеют только источник `interview`, происхождение и участие реальных специалистов не подтверждались.

## Материалы и приватность

- Продуктовый `POST /api/v1/runs/{id}/skill-model/extract` через локальный API и настроенную LLM `minimax-m3.1-flash` на `api.reformboss.com`.
- Два отдельных сохранённых исследования backend-разработчика: первое — 20 узлов/20 цитат; второе — 21 узел/24 цитаты. В базе у обоих указан тип источника `interview`.
- Десять синтетических случаев проверили различие знания/умения/владения, Python/PostgreSQL, отрицание применения Python, неполные сведения, требования вакансии, границу между инструментами и стандартами/протоколами, отклонённые цитаты и prompt injection.

Предложения показывались только как preview и не сохранялись в словари. После обоих вызовов словарь каждого исследования остался на ревизии `0` без связей. Для первого исследования JSON дерева до и после совпал полностью. Для второго предзапусковая и послезапусковая сводки показали одинаковые числа узлов и цитат. Одноразовые синтетические записи удалены; результаты вызовов находятся только в игнорируемом `.secrets/skill-quality/`.

Пользователь попросил проверить несколько исследований. Переданные внешней LLM материалы ограничились цитатами этих двух локальных деревьев; код использует короткие локальные ID вместо ID узлов, источников и интервью.

## Исправления, проверенные в этой серии

1. В запрос LLM передаётся тип источника. Прямое требование вакансии связывается с `basis=requirement`, но не считается опытом человека.
2. Инструментами считаются конкретные программные технологии. REST, GraphQL, OpenAPI, JWT, OAuth2, RBAC и scopes не добавляются в инструменты; Pull Request не даёт оснований выводить GitHub/GitLab или связывать Git с отправкой PR.
3. Повтор цитаты внутри одной связи удаляется; каждая цитата должна принадлежать указанному узлу. Неоднозначные или неизвестные ссылки остаются ошибкой.
4. Версия ссылки на ЗУН корректируется только при единственной доступной версии того же ID.
5. Неполное предложение «владение» понижается до «умения», если отсутствует любое обязательное поле: действие, объект, условия, результат, критерий, самостоятельность или диапазон ситуаций. Ранее сохранённые версии не меняются.
6. Связи и определения, предложенные моделью, остаются неподтверждёнными до ручной проверки.

В обоих реальных preview все связи имели статус `proposed`; ID определений и цитат разрешились, каждая цитата принадлежала тому же узлу, отклонённых оснований не было. Сохранённые ревизии остались `0`, число сохранённых связей — `0`. Не все узлы получили предложения: модель не должна создавать ЗУН только ради покрытия дерева.

При ручной проверке второго результата связи на SQL/PostgreSQL, `EXPLAIN ANALYZE` и интеграционные тесты опирались на цитаты тех же узлов. Названные в цитатах FastAPI, Pydantic, Passlib, pytest, Celery, Redis, RabbitMQ и HTTP-клиенты предлагались как конкретные инструменты, обычно необязательные, если цитата называла их примерами или альтернативами. Кандидаты на владение в обоих интервью не появились; явный синтетический пример с самостоятельностью, повторяемостью, несколькими сценариями и проверкой сохранил категорию `proficiency`.

## Ограничения

- Это два исследования одной роли, оба только с источником типа `interview`; разные записи не подтверждают, что это два реальных специалиста.
- Нет согласованного набора материалов реального пилота, проверенного методистом. Ни методист, ни специалисты для этой проверки не привлекались.
- 10 синтетических контролей и 2 существующих дерева не дают статистической оценки точности, полноты и устойчивости семантических связей для всех профессий.
- LLM-preview занял 48–105 секунд на вызов. Результаты всё ещё требуют проверки методистом; они не являются оценкой человека или доказательством его владения инструментом.
