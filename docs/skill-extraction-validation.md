# Проверка извлечения ЗУН реальной LLM — 21 ноября 2026

**Итог: проверка готовности к публикации НЕ пройдена. Push не выполнен.**

## Что проверялось

- Продуктовый `POST /api/v1/runs/{id}/skill-model/extract` через локальный nginx.
- Настроенный провайдер `api.reformboss.com`, основной аналитик
  `minimax-m3.1-flash`; в начальной сборке также вызывался настроенный fallback
  `deepseek-v4.1-flash-1017`.
- Существующее локальное backend-исследование: 20 узлов, 20 цитат. Его
  происхождение и участие реального специалиста отдельно не подтверждались.
  Это проверка на существующих материалах, а не утверждённый методический пилот.
- Девять искусственных случаев из `testdata/skill-extraction-cases.json`:
  перечень технологий, знание без практики, Python с PostgreSQL, архитектурная
  задача, явно описанное владение, неизвестные условия, требование вакансии,
  отклонённое основание и инструкция внутри документа.

Передача существующего дерева провайдеру была отдельно разрешена пользователем.
Результаты LLM не сохранялись в словарь исследования. Исходное дерево после
проверки точно совпало с исходным JSON, ревизия его словаря осталась 0.
Одноразовые исследования и источники контрольных случаев удалены.
Необработанные ответы и исходные цитаты оставлены только в игнорируемом локальном
каталоге `.secrets/skill-quality/`; в Git их нет.

## Обнаруженные и исправленные дефекты

1. Чистый JSON принимался, но реальный ответ в Markdown-блоке с примечанием
   отклонялся. Теперь принимается один JSON-блок; дополнительные JSON-пакеты,
   незакрытые блоки и неизвестные поля отклоняются.
2. Ответ ЗУН проверялся схемой дерева аналитика, вызывая ненужный fallback.
   Добавлен клиент с контрактом конкретной задачи при сохранении провайдера,
   guardrails, общего лимитера и аудита.
3. Модель путала версию определения и версию технологии. Контракт уточнён:
   версия инструмента — строка только при прямом указании в цитате. Числовая
   версия инструмента не преобразуется молча и отклоняется.
4. Ошибки копирования длинных ID узлов. Во входе LLM теперь короткие локальные
   ссылки с точным обратным отображением; неизвестные ссылки не угадываются.
5. Пропуск моделью неиспользуемых инструментов приводил к отклонению всего
   словаря. Существующие инструменты, определения и решения теперь сохраняет
   сервер; модель предлагает дополнения.
6. Фразы «условия не обсуждались» заполняли поле условий. Для новых предложений
   такие оговорки оставляют поле пустым и отмечаются в причине. Проверка
   полноты также не считает известными поля с явными оговорками об отсутствии
   сведений. Это консервативные правила для известных формулировок, а не
   универсальная семантическая классификация.
7. Из входа исключены ранее сгенерированные строковые ЗУН и лишние метаданные:
   они не должны становиться новым основанием вместо исходных цитат.

## Содержательная проверка

В успешном контрольном ответе:

- перечень технологий не стал знанием или умением;
- знание не повысилось до умения или владения;
- backend-задача сохранила Python и PostgreSQL;
- архитектурная задача не получила Python из отрицательного упоминания;
- явно описанное владение сохранило самостоятельность, ситуации и проверку;
- неизвестные условия и критерии остались незаполненными;
- не появились выдуманные версии инструментов;
- отклонённое основание и инструкция про Rust не породили ЗУН;
- ни одна связь не была подтверждена автоматически;
- **требование вакансии было пропущено**, поэтому контроль не пройден.

В успешном ответе на существующем дереве все 27 ссылок корректно относятся к
переданным узлам и цитатам, все связи имеют статус `proposed`. Выдуманных версий
инструментов нет. Примеры средств — Postman/curl, Alembic/Liquibase и Pydantic —
отмечены необязательными. Без прямого основания не приписаны Python или владение.

Ручная сверка обнаружила смысловые ограничения:

- «Создание веток и Pull Request» объединено в применение Git. Создание PR
  относится к платформе совместной работы; инструмент для него в цитате не назван.
- Описание RBAC/scopes связано с комбинированным определением JWT/OAuth2.
  Требуется разнести аутентификацию и проверку разрешений и уточнить, какую
  часть утверждения поддерживает каждая цитата.
- В отдельных `scope` появилась регулярность работы, не установленная именно
  приложенной цитатой. Наличие ссылки ещё не гарантирует такую интерпретацию.

В промежуточных вызовах также наблюдался пропуск SQL в инструментах
архитектурного случая. Общая полнота и смысловая эквивалентность не доказаны.

## Решение

Транспортный сценарий работает на существующем дереве; семантические и
ссылочные ошибки остаются. Эти результаты не позволяют объявить извлечение
надёжным или завершить проверку перед push успешно.

Следующие необходимые работы: ограниченное исправление ответа при ошибке
ссылок с повторной строгой проверкой; выявление пропущенных положительных
случаев без принудительного извлечения из недостаточных данных; разделение
близких действий и инструментов; повторный независимый контроль. Нельзя
ослаблять валидацию или угадывать неизвестные ID ради HTTP 200.

Регрессионные проверки изменённых Go-пакетов, TypeScript и 340 тестов фронтенда
прошли. Успех этих тестов не заменяет отрицательный результат живой проверки.

Контроль сохранённых ответов:

```powershell
python scripts/evaluate_skill_extraction.py .secrets/skill-quality/controls-verified-1.json .secrets/skill-quality/controls-verified-2.json
```

Ожидаемый результат этой команды на проверенных ответах — ненулевой код.
