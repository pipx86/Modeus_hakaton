# Проверка извлечения ЗУН и связей с инструментами — 21 ноября 2026

**Итог:** изменения проверены на двух завершённых backend-исследованиях и на двух независимых прогонах 12 синтетических случаев. Все четыре live preview вернули HTTP 200; оба синтетических прогона прошли все 26 контрольных условий. Это повторная инженерная проверка, а не пилот с методистом или подтверждёнными специалистами.

## Что проверялось

- Реальный маршрут `POST /api/v1/runs/{id}/skill-model/extract` через локальный API и настроенную LLM `minimax-m3.1-flash` на `api.reformboss.com`.
- Два сохранённых дерева backend-исследований: первое — 20 узлов/20 цитат, второе — 21 узел/24 цитаты; для обоих тип источника в базе — `interview`.
- Двенадцать синтетических фрагментов: знание, умение и владение; инструменты backend, аналитика данных и DevOps; SQL и PostgreSQL; отрицания и неизвестные сведения; требования вакансии; протоколы и стандарты; отклонённые основания; prompt injection.

Запросы к реальным исследованиям использовались только как preview: после них у обоих исследований GET по skill-model показал ревизию `0`, ноль сохранённых определений и ноль сохранённых связей. Предложения остались неподтверждёнными и не меняли деревья. Искусственные записи контроля удаляются скриптом после проверок. Результаты вызовов лежат в игнорируемом `.secrets/skill-quality/`.

В LLM передавались цитаты двух локальных деревьев. Исследования относятся к одной роли; нет подтверждения, что за ними стоят разные специалисты. Методист и реальные специалисты в проверке не участвовали.

## Исправления

1. В extraction prompt передаётся тип источника: требование вакансии связывается с `basis=requirement` и не трактуется как личный опыт.
2. Инструментами считаются конкретные технологии, прямо подтверждённые фрагментом. SQL и PostgreSQL разделены; Python и pandas не подменяют друг друга. Протоколы, стандарты, JWT/OAuth/RBAC и сам факт Pull Request не дают основания добавлять инструменты.
3. Ссылки на инструмент нормализуются по ID, имени или псевдониму только при однозначном совпадении с каталогом; повторяющиеся совпадения объединяются. Неизвестная или неоднозначная ссылка не подменяется догадкой.
4. Повторные ID цитат убираются. Если модель указала не тот узел, основание переносится к фактическому владельцу либо связь разделяется по владельцам. Неизвестное основание по-прежнему отклоняется строгой проверкой.
5. Неполный кандидат на «владение» понижается до «умения», если не хватает любого измерения: действия, объекта, условий, результата, критерия, самостоятельности или диапазона ситуаций. Сохранённые ранее версии не меняются.
6. LLM предлагает определения и связи, но не подтверждает их за методиста.

В первом результате 19 ссылок на основания ссылались на 17 уникальных цитат, во втором — 20 ссылок на 20 цитат. Повтор одной цитаты между разными ЗУН допускается, если она подтверждает оба.

## Проверки кода

- Evaluator для каждого из двух синтетических ответов вернул `passed=true` по всем 26 условиям.
- Точечные API-тесты на понижение неполного «владения», нормализацию ссылок на инструменты, привязку цитат к владельцам и границы extraction prompt прошли.
- `go vet ./internal/api ./internal/domain/...` прошёл.
- Полный `go test ./internal/api ./internal/domain/... -count=1` прошёл с разрешённым loopback для локальных `httptest` серверов. Тест `TestBulkApproveIdempotent` также проверяет ошибку первого HTTP-запроса вместо паники при недоступном loopback.
- Проверка синтетических ответов: `python scripts/evaluate_skill_extraction.py .secrets/skill-quality/controls-crossrole-push-1.json .secrets/skill-quality/controls-crossrole-push-2.json`.

## Ограничения

- Два реальных дерева относятся к одной роли и не заменяют проверку на согласованных материалах пилота.
- Контроли подтверждают заданные сценарии, но не оценивают статистическую точность на всех профессиях и корпусах.
- Число предложенных связей не является оценкой специалиста или доказательством его владения инструментом. Методист должен проверить цитату, контекст и смысл каждой связи.
