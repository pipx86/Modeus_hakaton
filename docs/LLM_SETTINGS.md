# Настройки LLM: матрица экспериментов (`cmd/llm-settings`)

`cmd/llm-settings` — маленький живой диагностический CLI: прогоняет одного
агента (интервьюер или аналитик) по сетке настроек модели и показывает, как
настройки влияют на задержку, валидность JSON и расход токенов. Одна ячейка
сетки — один реальный запрос к OpenAI-совместимому провайдеру.

Команда не меняет поведение продукта: она создаёт собственный клиент
`internal/llm/openai` на каждую ячейку, не использует общий шлюз
`internal/llm/agents` (лимиты, retry, circuit breaker, guardrails) и
предназначена для подбора `LLM_*` переменных вручную. Результаты можно
сохранить в JSON и приложить к ревью как воспроизводимые данные.

## Переменные окружения

Команда читает конфигурацию через `agents.FromEnv()`, поэтому действуют те же
правила, что и у продакшн-кода.

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `LLM_API_KEY` | — | ключ провайдера; обязателен для живого прогона |
| `LLM_API_KEY_FILE` | `.secrets/reformboss.key` | файл с ключом, если `LLM_API_KEY` не задан |
| `LLM_BASE_URL` | `https://api.reformboss.com/v1` | OpenAI-совместимый endpoint |
| `LLM_MODEL` | `deepseek-v4.1-flash-1017` | модель по умолчанию для всех агентов |
| `LLM_TIMEOUT_S` | `300` | таймаут в продакшн-конфиге (сам CLI его не использует, см. `-timeout`) |
| `LLM_MAX_CONCURRENCY` | `3` | лимит одновременных запросов продакшн-пула |
| `LLM_REQUESTS_PER_MINUTE` | `20` | лимит запросов в минуту продакшн-пула |
| `LLM_RETRY_MAX` | `3` | повторы на 429/5xx в продакшн-пуле |

Пер-агентные переопределения (`<AGENT>` = `INTERVIEWER`, `ANALYST`,
`SYNTHESIZER`):

| Переменная | Интервьюер | Аналитик | Синтезатор |
|---|---|---|---|
| `LLM_<AGENT>_MODEL` | `LLM_MODEL` | `LLM_MODEL` | `LLM_MODEL` |
| `LLM_<AGENT>_TEMPERATURE` | `0.4` | `0.2` | `0.1` |
| `LLM_<AGENT>_MAX_TOKENS` | `1500` | `5000` | `4000` |
| `LLM_<AGENT>_TIMEOUT_S` | `LLM_TIMEOUT_S` | `LLM_TIMEOUT_S` | `LLM_TIMEOUT_S` |
| `LLM_<AGENT>_REASONING_EFFORT` | `low` | `low` | `low` |

`cmd/llm-settings` использует generic-переменные `LLM_*`. Старые
`OPENROUTER_*` (и файл `.secrets/openrouter.key`) всё ещё поддерживаются
`FromEnv` для обратной совместимости, но для новых прогонов их лучше не
использовать.

## Быстрый старт без сети (CI и локальные тесты)

`-dry-run` печатает эффективные настройки и полную сетку, не делает ни одного
сетевого вызова и не требует ключа:

```powershell
go run ./cmd/llm-settings -dry-run
```

Пример вывода (модель/лимит токенов берутся из конфига выбранного агента,
температуры — из дефолта флага):

```text
mode:            dry-run (no network calls)
agent:           interviewer
contract:        agent.io/v1
prompt:          interviewer v1 (sha256 dcfe4d70aec8)
provider:        https://api.reformboss.com/v1
api key:         not configured (dry-run only)
reasoning:       low
request timeout: 2m0s
repeats:         1
plan:            2 settings x 1 repeats = 2 requests

planned matrix (2 settings x 1 repeats = 2 requests, no network calls)
   1. model=deepseek-v4.1-flash-1017 temperature=0.20 max_tokens=1500 timeout=2m0s
   2. model=deepseek-v4.1-flash-1017 temperature=0.40 max_tokens=1500 timeout=2m0s
```

Тесты пакета тоже офлайновые: `go test ./cmd/llm-settings`.

## Живые прогоны

Ключ и провайдер нужны только для живого режима. Каждая ячейка — платный
запрос к провайдеру, поэтому сначала проверьте размер сетки через `-dry-run`.

```powershell
$env:LLM_API_KEY = '<ключ>'   # или файл, см. LLM_API_KEY_FILE

# Интервьюер: температура и лимит токенов
go run ./cmd/llm-settings `
  -agent interviewer `
  -models "deepseek-v4.1-flash-1017" `
  -temperatures "0.2,0.4,0.6" `
  -max-tokens "800,1500" `
  -timeout 120s `
  -repeat 3 `
  -out interviewer-settings.json

# Аналитик: почти детерминированное извлечение и длинный JSON
go run ./cmd/llm-settings `
  -agent analyst `
  -temperatures "0,0.2" `
  -max-tokens "3000,5000" `
  -timeout 180s `
  -out analyst-settings.json
```

`-agent` принимает только `interviewer` и `analyst`: у них есть стабильные
JSON-схемы (`internal/agent/schema/*.output.schema.json`), по которым CLI
проверяет сырой ответ через `agent.ValidateOutput`.

## Флаги

| Флаг | По умолчанию | Смысл |
|---|---|---|
| `-agent` | `interviewer` | `interviewer` или `analyst` |
| `-models` | модель из конфига `-agent` | список моделей через запятую |
| `-temperatures` | `0.2,0.4` | список температур через запятую, допустимо `0..2` |
| `-max-tokens` | лимит из конфига `-agent` | список лимитов через запятую, целые `> 0` |
| `-timeout` | `120s` | таймаут каждого запроса; не наследует `LLM_*_TIMEOUT_S` |
| `-repeat` | `1` | повторов на каждую ячейку сетки |
| `-out` | — | путь JSON-отчёта (эффективные настройки + ячейки) |
| `-strict` | `false` | ненулевой exit code, если не все запросы успешны и валидны |
| `-dry-run` | `false` | только печать плана и эффективных настроек, без сети |

Сетка строится как `models × temperatures × max-tokens × repeat`, порядок
обхода детерминирован: модели во внешнем цикле, затем температуры, затем лимиты
токенов. Дубликаты в списках удаляются.

## Как читать результаты

На каждый запрос CLI печатает строку прогресса, а в конце — таблицу:

```text
MODEL                       TEMP  MAX_TOKENS  SUCCESS  JSON  DURATION_MS  TOKENS  ERROR  PREVIEW
deepseek-v4.1-flash-1017    0.20  1500        true     true  3412         812            {"question":...
```

- `SUCCESS` — запрос завершился и вернул непустой ответ;
- `JSON` (`json_valid`) — сырой ответ прошёл `agent.ValidateOutput` по схеме
  агента; невалидный JSON не прерывает прогон, его причина пишется в
  `json_error`;
- `DURATION_MS` — время запроса; `TOKENS` — суммарные токены из observer-а
  `openai.WithUsageObserver`, если провайдер их вернул;
- `ERROR` — ошибка запроса; `PREVIEW` — первые 60 символов ответа (в JSON —
  до 200 символов).

Exit code: `0` — прогон завершён и хотя бы одна ячейка успешна; `1` — все
ячейки упали, либо `-strict` и есть неуспешная/невалидная ячейка; `2` — ошибка
флагов или конфигурации (например, нет ключа). Ключ никогда не печатается:
вместо него `api key: configured (hidden)`, а случайно попавший в текст ошибки
ключ заменяется на `[redacted]`.

Если запланировано больше 20 живых запросов, CLI предупреждает о стоимости.
При `-out` JSON-отчёт содержит `dry_run`, `base_url`, версию и sha256 промпта,
эффективный таймаут, число повторов, полную сетку, ячейки и сводку `summary` —
этого достаточно, чтобы повторить эксперимент и сравнить результаты.

## Как выбирать настройки

**Интервьюер** — творческая задача, но с жёстким JSON-контрактом. Начните с
температуры `0.2`–`0.6` и лимита `800`–`1500` токенов: слишком высокая
температура чаще ломает JSON и придумывает ответы за респондента, слишком
низкая делает вопросы шаблонными. Сравнивайте не только `json_valid`, но и
разнообразие вопросов между повторами (`-repeat 3`).

**Аналитик** — точное извлечение с дословными цитатами, поэтому температура
`0`–`0.2`, а лимит токенов заметно выше (`3000`–`6000`): ответ — длинный JSON,
и обрезка по токенам проявляется как невалидный/неполный JSON. Для медленных
reasoning-моделей ставьте `-timeout 180s` и больше; таймаут в таблице видно как
ошибку запроса, а не как невалидный JSON.

Общие правила:

1. Сначала `-dry-run`, чтобы посчитать ячейки и стоимость.
2. Для каждого кандидата — `-repeat 3`: на одном прогоне вывод модели шумный.
3. Отбрасывайте настройки, где `json_valid` ниже 100% на повторах: продакшн
   всё равно сделает repair/fallback, но это лишние вызовы и задержка.
4. Проверяйте `p95` задержки и запас по `max_tokens`, а не только средние.
5. Найденные значения закрепите в `LLM_<AGENT>_TEMPERATURE`,
   `LLM_<AGENT>_MAX_TOKENS`, `LLM_<AGENT>_TIMEOUT_S` и проверьте продакшн-путь
   `go test ./internal/llm/...`.

## Ограничения

- Каждая ячейка — отдельный прямой вызов провайдера без retry, circuit breaker
  и guardrails продакшн-пула; это осознанно: эксперимент измеряет «чистую»
  модель и промпт, а не обвязку. Сетка выполняется последовательно.
- `-dry-run` не проверяет доступность провайдера и правильность ключа.
- Синтезатор в CLI не поддерживается: у него нет включённой в этот инструмент
  отдельной ветки эксперимента.
- Живой прогон требует `LLM_API_KEY` и тратит деньги. Не коммитьте ключи и
  `.secrets/`; отчёт `-out` ключ не содержит, но превью ответов модели могут
  быть чувствительными — проверяйте перед публикацией.
