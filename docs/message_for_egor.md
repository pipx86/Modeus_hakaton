Егор, в твоей ветке подготовлены следующие изменения бэкенда.

1. Сервер подключён к PostgreSQL через PGStore: данные исследований, дерева, подтверждений и одобрение теперь сохраняются. Добавлен метод Save для передачи постоянного хранилища в ваш оркестратор. Поля status и stage сохраняются вместе с временем; SSE читает сохранённый этап.
2. Добавлен PUT /api/v1/runs/{id}/tree. Принимает плоский список узлов, возвращает 422 с code/details при ошибках дерева. Доступ по вашим JWT-ролям admin/teacher/rop. Используется существующий sqlc/store, запись дерева атомарна; замена готового дерева пока не предусмотрена.
3. Сервер больше не требует старый общий API_TOKEN поверх JWT. Настройки запуска: DATABASE_URL, JWT_SECRET, опционально HTTP_ADDR.
4. Добавлены POST /api/v1/sources/{id}/index и GET /api/v1/runs/{id}/search. Индексация обращается к Ollama, при сбое поиска по вектору используется BM25. Ошибка индексации сохраняет прежний индекс.
5. Загрузчики вакансий (hh.ru/JSON/CSV), профстандартов (текстовый PDF/JSON), таксономий (JSON/CSV) и программ (JSON, размеченный текст или типовые разделы УК/ОПК/ПК и Знать/Уметь/Владеть) находятся в cmd/ingest. Есть проверка формата, повторного импорта и отчёт о несопоставленных кодах.

Миграции остались в ветке Рустама feature/rustam/goose-migrations. Для этого кода надо применить их до 20261110000000_run_stage.sql; для поиска ещё нужен отдельный пакет migrations_optional/vector с pgvector. Сами SQL-миграции в твою ветку не копировались.

Проверки: полный go test ./... с тестовой PostgreSQL; сценарий API → sqlc/store → оркестратор → PostgreSQL → экспорт; проверка создания run.completed; ошибки 422 и откат при несуществующем источнике; переключение vector/BM25 и сохранение старого индекса при сбое модели. В общем сценарии шаги агентов тестовые.

Ограничения на момент проверки: реальный hh.ru ответил 403, настроенного HH_ACCESS_TOKEN в окружении нет. Загрузка весов настоящей Ollama не завершилась из-за сетевого окружения; тест десяти запросов к модели написан, но пока не подтверждён на реальной модели. Автоматический запуск настоящих агентов при POST создания исследования и реальный n8n ещё нужно соединить и проверить. Идемпотентность API по-прежнему использует ваш текущий механизм.

Дополнительно: strategy=hybrid объединяет ранги BM25 и vector через RRF. Подготовлены Windows-скрипты настройки hh.ru с DPAPI-хранением токена вне репозитория. Используется только уже действующий токен; запросов выдачи и отзыва в скриптах нет. Для авторизованной проверки нужен локальный доступ к действующему токену.
