# Импорт образовательных программ

Как занести программу, компетенции и KSA в систему и что происходит дальше.

## Зачем

Сопоставление деятельности с программой работает только если в базе есть сама
программа: её компетенции и знания/умения/навыки. Мы не парсим вузовские
документы «как получится»: сначала импорт создаёт **черновик**, методист
проверяет его, и только потом данные становятся рабочими.

## Форматы

Поддерживаются CSV, XLSX, JSON, TXT и MD. Для вузов основной формат - XLSX
(три листа), для технических людей - CSV (один файл). PDF и DOCX разбирает
LLM-адаптер ФГОС: он извлекает компетенции, KSA и дословные цитаты с номерами
страниц. Сканы PDF и изображения PNG/JPEG распознаёт OCR, если он включён
(`OCR_ENABLED=true`). Подробности, включение и ограничения — в
[13-fgos-llm.md](13-fgos-llm.md) и [14-ocr.md](14-ocr.md).

### CSV

Один файл, разделитель `;` или `,`, UTF-8 (BOM допускается).

```csv
kind;code;title;parent_code;taxonomy_codes;type
program;09.03.01;Информатика и вычислительная техника;;;
competency;УК-1;Системный анализ;;"T1;T2";УК
competency;ОПК-2;Разработка ПО;;T3;ОПК
knowledge;УК-1;Методы системного анализа;УК-1;T1;
skill;ОПК-2;Проектировать модули;ОПК-2;T3;
```

- `kind` - `program`, `competency`, `knowledge`, `skill`, `ability`;
- `parent_code` у KSA ссылается на код компетенции;
- `taxonomy_codes` - коды таксономии через `;` (в CSV экранировать кавычками);
- `type` - тип компетенции: `universal`, `general_professional`, `professional`,
  `other` или по-русски `УК`, `ОПК`, `ПК`, `иное`.

### XLSX

Три листа: `Программа`, `Компетенции`, `KSA`. Шапки регистронезависимые,
порядок колонок любой.

**Программа:** `title`, `code`, `organization`.

**Компетенции:** `code`, `title`, `type`, `taxonomy_codes`.

**KSA:** `competency_code`, `kind`, `title`, `taxonomy_codes`.

### JSON и текст

JSON - канонический формат из кода (`EducationProgram`). TXT/MD - построчный
формат: `компетенция: КОД | Название`, затем `знание: ...`, `умение: ...`,
`навык: ...`.

## Как проходит импорт

1. Администратор открывает «Администрирование» и карточку «Импорт
   образовательной программы».
2. Указывает постоянный код программы (например, `mgu/01.03.02/2026/full-time`)
   и выбирает файл.
3. Система разбирает файл и создаёт **черновик**: показывает название, код,
   организацию, таблицу компетенций с типом и KSA, а также предупреждения
   (пустой тип, KSA без родителя, неизвестные строки).
4. Администратор проверяет и нажимает «Опубликовать» (можно указать таксономию
   для сопоставления кодов) или «Отклонить».
5. После публикации показывается отчёт: сколько компетенций и KSA не удалось
   сопоставить с таксономией и какие коды оказались неизвестны.

Черновик не влияет на рабочие данные: пока он не опубликован, сопоставление с
программой не использует его.

## API

| Метод и путь | Что делает |
|---|---|
| `POST /api/v1/admin/programs/import` | multipart: `file` + `key`; создаёт черновик (201), 422 при ошибках разбора (включая PDF/DOCX без настроенной LLM и сканы без OCR), 503 если LLM или OCR недоступны. PDF/DOCX и сканы разбираются синхронно с бюджетом `PROGRAM_IMPORT_TIMEOUT_S` (по умолчанию 15 минут) |
| `GET /api/v1/admin/programs/drafts` | список последних черновиков |
| `GET /api/v1/admin/programs/drafts/{id}` | черновик с программой и отчётом |
| `POST /api/v1/admin/programs/drafts/{id}/publish` | публикация, тело `{taxonomy?}`; 409 при повторной публикации |
| `POST /api/v1/admin/programs/drafts/{id}/reject` | отклонение (204), 409 если решение уже принято |

Все маршруты требуют роль `admin`. На in-memory хранилище (демо без PostgreSQL)
раздел отвечает 501.

## Ограничения

- Публикация и смена статуса черновика выполняются двумя запросами, полной
  атомарности нет: при гонке второй запрос получит 409, но SaveEducation
  идемпотентен по `key`.
- CSV с `;` требует кавычек для списка кодов таксономии.
- Файл читается целиком, лимит 20 МБ.
- TXT/MD без кода программы берут код из `key` с предупреждением.
- XLSX читается библиотекой `excelize`; сложные объединённые ячейки могут
  разбираться неидеально, поэтому проверка человеком обязательна.

## Реестр источников и воркер

Чтобы программы появлялись сами, есть реестр `program_watch_sources` и воркер.

Админка, карточка «Источники программ»:

- добавить источник: ключ `{org}/{code}/{year}/{form}`, URL, интервал в часах;
- список со статусом последней проверки и ссылкой на созданный черновик;
- «Проверить сейчас», включение/выключение, удаление.

Воркер `cmd/program-watcher`:

- берёт источники, у которых `last_checked_at + interval_hours <= now()`,
  не больше пяти за цикл;
- делает условный GET (`If-None-Match`, `If-Modified-Since`);
- хранит отпечаток не только страницы, но и привязанного документа:
  `document_url`, `document_hash`, `document_etag`, `document_last_modified`;
- проверяет документ отдельным условным GET и только потом решает, изменился ли
  источник: обновление xlsx/pdf по неизменившейся странице больше не теряется;
- 304 страницы или документа, либо тот же хэш страницы/документа - `unchanged`;
- HTML - ищет первую ссылку на документ программы
  (`.xlsx/.csv/.json/.txt/.md/.pdf/.docx`) и скачивает её;
- документ - `ParseProgramFile` и новый черновик, статус `changed`;
- PDF и DOCX - LLM-адаптер ФГОС и новый черновик, статус `changed`; без
  флага `-pdf-llm` (или без настроенной LLM) - статус `needs_parser`;
- ошибки - статус `error`, старые данные не трогаются, пауза растёт.

Запуск:

```bash
go run ./cmd/program-watcher -interval=15m
go run ./cmd/program-watcher -once
go run ./cmd/program-watcher -once -pdf-llm
```

## Что дальше

- OCR для сканов PDF и изображений: включается `OCR_ENABLED=true`, требует
  tesseract и poppler; лимиты и установка — в [14-ocr.md](14-ocr.md);
- фоновая очередь разбора PDF/DOCX, чтобы импорт не ждал LLM синхронно;
- хранение цитат и номеров страниц в черновике, чтобы методист видел
  обоснование каждой компетенции прямо в карточке проверки.

## Добавление KSA из ОПОП или РПД

У ФГОС нет знаний и умений по компетенциям: их задаёт программа вуза. Поэтому
после импорта ФГОС в черновик можно загрузить второй документ (ОПОП, РПД) и
дополнить компетенции.

- `POST /api/v1/admin/programs/drafts/{id}/ksa`, multipart `file`
  (PDF, DOCX, TXT, MD); только администратор;
- модель вытаскивает пары «код компетенции → знать/уметь/владеть»;
- KSA дописываются только к существующим кодам, дубли не создаются;
- в ответе: `added`, `already_present`, `unknown_codes`, `warnings`;
- коды, которых нет в программе, возвращаются в `unknown_codes` и не создают
  новые компетенции;
- повторная загрузка того же файла идемпотентна: `added = 0`.

В интерфейсе: карточка черновика → кнопка «Добавить KSA» → выбрать файл.
