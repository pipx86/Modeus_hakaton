# Что мы сделали

Коротко: мы собрали сервис, который **разговаривает со специалистом и превращает
разговор в понятное описание его работы** - дерево «роль → функция → задача →
действие», где каждое утверждение подкреплено цитатой из источника.

Зачем это нужно: методистам и HR, которые описывают профессии и образовательные
программы, обычно приходится вручную интервьюировать людей, читать вакансии и
стандарты, а потом сводить это в таблицы. Мы автоматизировали этот путь и
оставили человеку главное - проверку.

## Как это выглядит для пользователя

1. **Создать исследование** - выбрать профессию (например, «Аналитик данных») и,
   если нужно, образовательную программу.
2. **Пройти интервью в чате** - агент задаёт вопросы по уровням: роль, функции,
   задачи, конкретные действия. Отвечать можно как в обычном мессенджере.
3. **Получить дерево деятельности** - система сама собирает его из ответов и
   приложенных материалов: вакансий, документов, стандартов.
4. **Проверить результат** - методист подтверждает или отклоняет узлы и цитаты,
   видит спорные места (конфликты источников) и что изменилось между версиями.
5. **Сопоставить с программой** - увидеть, какие компетенции программы покрыты
   деятельностью, а какие нет, и получить предложения по изменениям.

## Что внутри

- **Основа**: сервер на Go, база PostgreSQL. Дерево хранится в базе с проверками:
  один корень, правильные уровни, без циклов и дублей, у каждого узла есть
  хотя бы одно обоснование - «голых» утверждений система не пропускает.
- **Интерфейс**: веб-приложение на React. Вся работа - на одной странице
  исследования: источники, чат, дерево, обоснования, конфликты, программа.
- **Искусственный интеллект**: агент-интервьюер задаёт вопросы, аналитик
  извлекает узлы и цитаты, синтезатор сводит несколько источников и честно
  показывает разногласия, а не выбирает одно молча.
- **Надёжность**: если анализ упал (например, недоступна модель), ответы не
  теряются - есть кнопка «Повторить анализ». Сервер переживает перезапуск и
  продолжает диалог с того же места.
- **Для показа**: три демо-учётки (администратор, специалист, пользователь),
  встроенный сценарий интервью и команда, которая проводит его целиком.

## Что проверено

- около 300 автотестов интерфейса и более 200 тестовых файлов на бэкенде,
  включая проверки на гонки;
- линтеры, проверка типов и сборка - в автоматическом конвейере (CI);
- живой прогон: интервью с 5 ответами → дерево из 14 узлов и 14 цитат;
- повторный анализ упавшего прогона и запрет двойного запуска.

## Чего пока нет

- персональные планы обучения и «аватар интервьюера» - сознательно отложены;
- часть аналитических разделов (прогнозы, A/B-сравнение промптов) выключена
  флагом и в демонстрацию не входит;
- пилот на реальных людях - следующий шаг: подписать решение, провести
  интервью, собрать замечания.

## Как посмотреть

```bash
docker compose up -d postgres migrate
go run ./cmd/server          # API на http://127.0.0.1:8080
cd frontend && npm ci && npm run dev
```

Демо-учётки: `admin@modeus.local` / `Admin12345`, `specialist@modeus.local` и
`user@modeus.local` / `User12345` (создаются командой `go run ./cmd/seed-demo-users`).

Подробности - в `docs/mvp/` (методика, сценарий интервью, план пилота, повтор
анализа) и в `README.md` (запуск, стек, API).
