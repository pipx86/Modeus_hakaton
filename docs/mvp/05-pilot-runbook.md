# Актуальные границы пилота

Готовим три направления: backend-разработчик (junior, middle, senior), аналитик данных и DevOps-разработчик. Выбор программы и участие специалиста и методиста отложены до отдельного обсуждения. ## 0. Что считается полным прогоном

Один прогон — это **одно исследование, один респондент, одна программа,
`result_kind=program`**, пройденное от создания до передачи методисту:

1. интервью по сценарию [04-interview-script.md](04-interview-script.md) даёт
   2–3 недавних случая с действиями, инструментами, результатами и границами;
2. исследование финализировано со статусом `done`;
3. дерево прошло пороги: 1 `role`, ≥2 `function`, ≥4 `task`, ≥8 `action`, у
   каждого узла есть обоснование;
4. конфликты источников зафиксированы;
5. сводка проверки сходится с деревом;
6. для программы построены предложения сопоставления и рассчитано покрытие;
7. пакет передан методисту, замечания начаты.

Не считается полным прогоном: запуск на демо-API с in-memory store; прогон без
выбранной программы; интервью без согласия; дерево, полученное правкой БД или
подстановкой узлов; «успех» при статусе `degraded` или `failed`.

|---|---|---|---|

| ☐ | Промпты и конфигурация поддерживают профессию | Раздел «Роли пилота» в `prompts/interviewer/v1/system.md`, шаблоны тем; сейчас только аналитик данных, DevOps, backend, а «оператор» запрещён | Стоп: IT-вопросы сделают прогон недействительным |

Проверки `health` и `ready` намеренно разные: `health` отвечает, что процесс жив,
`ready` — что подключена PostgreSQL и схема актуальна. Для пилота нужны обе.

## 2. Переменные и доступ

```powershell
$BaseUrl = "http://127.0.0.1:8080"
$ProgramId = "<program_id из decision record>"
$Profession = "Техник-механик"

# Токен — только из окружения или параметра; не коммитить и не писать в файл.
$env:MODEUS_TOKEN = "<admin-token>"
$headers = @{ Authorization = "Bearer $env:MODEUS_TOKEN" }
```

Если токена нет, его выдаёт логин (пароль тоже не хранить в репозитории):

```powershell
$login = Invoke-RestMethod -Method Post -Uri "$BaseUrl/api/v1/auth/login" `
  -ContentType "application/json" `
  -Body (@{ email = $env:MODEUS_EMAIL; password = $env:MODEUS_PASSWORD } | ConvertTo-Json)
$env:MODEUS_TOKEN = $login.token
$headers = @{ Authorization = "Bearer $env:MODEUS_TOKEN" }
```

Токен живёт 24 часа. Роль `admin` нужна для конфликтов и снимков; роль `user`
достаточно для создания исследования и чтения дерева, но не для всех шагов.

### 2.1. Те же вызовы через curl

```bash
BASE_URL="http://127.0.0.1:8080"
TOKEN="<admin-token>"
PROGRAM_ID="<program_id>"
RUN_ID="<run_id>"

curl -sS "$BASE_URL/api/v1/health"
curl -sS "$BASE_URL/api/v1/ready"
curl -sS "$BASE_URL/api/v1/academic/programs/$PROGRAM_ID" -H "Authorization: Bearer $TOKEN"

curl -sS -X POST "$BASE_URL/api/v1/runs" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d "{\"profession\":\"Техник-механик\",\"type\":\"chat\",\"result_kind\":\"program\",\"program_id\":\"$PROGRAM_ID\"}"

curl -sS -X POST "$BASE_URL/api/v1/runs/$RUN_ID/messages" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"content":"В начале смены принимаю оборудование и проверяю журнал."}'

curl -sS "$BASE_URL/api/v1/runs/$RUN_ID" -H "Authorization: Bearer $TOKEN"
curl -sS "$BASE_URL/api/v1/runs/$RUN_ID/tree" -H "Authorization: Bearer $TOKEN"
curl -sS "$BASE_URL/api/v1/runs/$RUN_ID/conflicts" -H "Authorization: Bearer $TOKEN"
curl -sS "$BASE_URL/api/v1/runs/$RUN_ID/review/summary" -H "Authorization: Bearer $TOKEN"
curl -sS -X POST "$BASE_URL/api/v1/runs/$RUN_ID/program-links/generate" -H "Authorization: Bearer $TOKEN"
curl -sS "$BASE_URL/api/v1/runs/$RUN_ID/program-coverage" -H "Authorization: Bearer $TOKEN"
```

В curl тело с кириллицей отправляется в UTF-8; в PowerShell для этого явно
кодируются байты (`[Text.Encoding]::UTF8.GetBytes(...)`), иначе Windows PowerShell
5.1 может отправить текст в однобайтовой кодировке.

## 3. Шаги прогона

### Шаг 1. Проверить стенд

```powershell
Invoke-RestMethod "$BaseUrl/api/v1/health"
Invoke-RestMethod "$BaseUrl/api/v1/ready"
```

**Ожидаемо:** `200` и `{"status":"ok"}` у обоих; у `ready` — `problems: []`.
**Приёмка:** оба 200. `ready` = 503 означает `db_pool_unavailable`,
`db_unavailable` или `schema_not_ready` — прогон не начинается.

### Шаг 2. Проверить программу

```powershell
$program = Invoke-RestMethod "$BaseUrl/api/v1/academic/programs/$ProgramId" -Headers $headers
$program.title
@($program.competencies).Count
(@($program.competencies | ForEach-Object { @($_.ksa).Count }) | Measure-Object -Sum).Sum
```

**Ожидаемо:** `200`; название совпадает с decision record; ≥3 компетенции; ≥5 KSA.
**Приёмка:** пороги выполнены, версия и документ-основание вписаны в решение.
Если меньше — либо дополнить программу, либо зафиксировать уменьшенный объём
(только компетенции) в карточке 2 и запускать с этим ограничением.

### Шаг 3. Создать исследование

```powershell
$body = @{
  profession  = $Profession
  type        = "chat"
  result_kind = "program"
  program_id  = $ProgramId
} | ConvertTo-Json

$run = Invoke-RestMethod -Method Post -Uri "$BaseUrl/api/v1/runs" -Headers $headers `
  -ContentType "application/json; charset=utf-8" `
  -Body ([Text.Encoding]::UTF8.GetBytes($body))

$runId = $run.id
$run | Select-Object id, status, stage, result_kind, program_id
```

**Ожидаемо:** `201`; есть `id`; `result_kind=program`; `program_id` совпадает;
`stage=interview`. **Статус чат-исследования:** в ответе на создание может быть
`pending`, после перехода в стадию интервью — `running`; это нормально. Смотрите
на `stage` и на ответы интервьюера, а не только на `status`.

**Приёмка:** `runId` сохранён; `stage=interview`; `program_id` совпадает.
Ошибки: `400` «chat pipeline is not available» — не настроен чат/LLM; `401` —
токен; `422 INVALID_PROGRAM` — программы нет в справочнике; `503
LLM_UNAVAILABLE` — модель недоступна для анализа транскрипта.

### Шаг 4. Провести интервью

#### 4.1. Живое интервью

Респондент отвечает в интерфейсе исследования; те же ответы можно отправлять
через API:

```powershell
$answer = @{ content = "В начале смены принимаю оборудование, проверяю давление и наличие заготовок." } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri "$BaseUrl/api/v1/runs/$runId/messages" -Headers $headers `
  -ContentType "application/json; charset=utf-8" `
  -Body ([Text.Encoding]::UTF8.GetBytes($answer))
```

**Ожидаемо:** `201`; интервьюер задаёт следующий вопрос.
`409 QUESTION_PENDING` / `409 CHAT_CONFLICT` — вопрос ещё генерируется, повторить
через 3–5 секунд. `409 SESSION_FINISHED` — интервью завершено, ответы больше не
принимаются. `409 SESSION_INTERRUPTED` — сессия потеряна при перезапуске сервера:
исследование нужно начинать заново, а не «дописывать».

**Приёмка:** 2–3 недавних случая с датой/триггером; в каждом 3+ наблюдаемых
действия; названы инструмент, результат, время/частота и границы «сам / команда /
система»; наводящих вопросов — 0; интервью 20–40 минут. Ответы без ФИО,
контактов и названий организаций.

#### 4.2. Replay транскрипта

Если живой респондент недоступен, тот же чат-прогон можно воспроизвести из
файла: **одна строка — один ответ респондента**, пустые строки и строки,
начинающиеся с `#`, игнорируются; строки интервьюера (`И:`, `Интервьюер:`,
`Q:`) пропускаются; префикс `Р:` / `Респондент:` срезается.

```text
# Интервью Р-01, 2026-11-20, обезличено
Р: В начале смены принимаю оборудование у предыдущего оператора и проверяю журнал.
Р: Если давление воздуха ниже нормы, останавливаюсь и вызываю наладчика.
...
```

```powershell
pwsh -NoProfile -File scripts/pilot/run-scenario.ps1 `
  -BaseUrl $BaseUrl `
  -Profession $Profession `
  -ProgramId $ProgramId `
  -TranscriptPath ".\pilot\interview-R-01.txt"
```

Скрипт отправляет ответы по одному, ждёт, пока интервьюер задаст следующий
вопрос, затем ждёт финализации и печатает чек-лист. Replay не заменяет живое
интервью: он проверяет техническую цепочку и даёт материал для методиста, но
согласие и протокол всё равно нужны.

**Приёмка replay:** отправлено не меньше 5 содержательных ответов; исследование
дошло до `done`; если интервьюер завершился раньше, лишние строки не отправлены и
это отмечено, а не замаскировано.

### Шаг 5. Дождаться финализации

```powershell
while ($true) {
  $run = Invoke-RestMethod "$BaseUrl/api/v1/runs/$runId" -Headers $headers
  "{0} / {1}" -f $run.status, $run.stage
  if ($run.status -in @("done", "degraded", "failed")) { break }
  Start-Sleep -Seconds 10
}
```

**Ожидаемо:** `done / done`; ориентир — до 60 минут после последнего ответа
(финализатор ограничен 60 минутами).
**Приёмка:** только `done`. `degraded` — частичный результат: дерево может быть
неполным; `failed` — анализ не выполнен, ответы сохранены. Оба статуса
фиксируются в журнале замечаний, а не выдаются за успех.

**Таймаут:** если спустя 90 минут статус всё ещё `pending`/`running` или стадия
`interview`/`analysis`/`synthesis`, прогон останавливается как неудачный; не
перезапускайте финализатор вручную и не правьте БД.

### Шаг 6. Получить и проверить дерево

```powershell
$tree = Invoke-RestMethod "$BaseUrl/api/v1/runs/$runId/tree" -Headers $headers
$tree.nodes.Count
$tree.nodes | Group-Object type | Select-Object Name, Count
@($tree.nodes | Where-Object { @($_.evidence).Count -eq 0 }).Count
$tree | ConvertTo-Json -Depth 20 | Set-Content -Encoding UTF8 ".\pilot\tree-$runId.json"
```

**Ожидаемо:** `200`; `nodes` — плоский список; типы `role/function/task/action`.
**Приёмка:** ровно 1 `role`; ≥2 `function`; ≥4 `task`; ≥8 `action`; у каждого узла
≥1 обоснование. Спорные узлы помечены, отклонённые обоснования объяснены — это
проверяет методист, но пустых обоснований быть не может.

`insights.health` — детерминированная подсказка, а не приёмка: она не заменяет
проверку цитат и уровней человеком.

### Шаг 7. Зафиксировать конфликты

```powershell
$conflicts = Invoke-RestMethod "$BaseUrl/api/v1/runs/$runId/conflicts" -Headers $headers
$conflicts.Count
```

**Ожидаемо:** `200`, массив (возможно пустой). У каждого конфликта есть `node_id`,
`field`, конкурирующие `values`, `winner` и `reason`; приоритет источников —
интервью > профстандарт > вакансия > документ.
**Приёмка:** все конфликты имеют победителя и причину; пустой список — тоже
результат, но он фиксируется в пакете. `403` — токен не admin; `501` — нет
PostgreSQL. Конфликты не редактируются вручную: это материал для методиста.

### Шаг 8. Сверить сводку проверки

```powershell
$summary = Invoke-RestMethod "$BaseUrl/api/v1/runs/$runId/review/summary" -Headers $headers
$summary.nodes
$summary.evidence
$summary.links
```

**Ожидаемо:** `200`; `nodes.total` равно числу узлов дерева; `evidence.total` равно
сумме обоснований; `links.total` — числу предложенных/проверенных связей.
**Приёмка:** счётчики сходятся. `pending > 0` до проверки методистом — норма, а не
ошибка: подтверждение обоснований — следующий этап.

### Шаг 9. Построить сопоставление и покрытие

```powershell
$links = Invoke-RestMethod -Method Post -Uri "$BaseUrl/api/v1/runs/$runId/program-links/generate" -Headers $headers
$links.Count

$coverage = Invoke-RestMethod "$BaseUrl/api/v1/runs/$runId/program-coverage" -Headers $headers
$coverage.program_id
$coverage.counts
$coverage.competencies
```

**Ожидаемо:** `200` от генерации и ≥1 предложение `proposed`; `200` от покрытия,
`program_id` совпадает, `counts.total` равно числу узлов,
`confirmed + proposed + none = total`.
**Приёмка:** предложения существуют, покрытие рассчитано; у методиста есть
очередь `proposed`. Связи — **предложения, а не факт**: утверждение и отклонение
делает методист, скрипт этого не делает.

Ошибки: `422 PROGRAM_NOT_SELECTED` — исследование создано без программы;
`422 PROGRAM_EMPTY` — в программе нет компетенций/KSA; `422 TREE_WITHOUT_EVIDENCE`
— дерево без пригодных оснований; `502 MATCHER_*` — модель вернула невалидный
ответ; `503 MATCHER_UNAVAILABLE` — модель сопоставления не настроена.

### Шаг 10. Передать методисту

Снимок дерева создаётся при генерации сопоставления; при необходимости
зафиксируйте версию отдельно:

```powershell
Invoke-RestMethod -Method Post -Uri "$BaseUrl/api/v1/runs/$runId/snapshots" -Headers $headers
```

Пакет передачи:

| Артефакт | Откуда | Критерий полноты |
|---|---|---|
| `run_id`, ссылка на исследование | шаг 3 | Интерфейс открывается, владелец совпадает |
| Decision record | [02-pilot-decision.md](02-pilot-decision.md) | Подписан, ID/версия/дата заполнены |
| Дерево и снимок | `GET /runs/{id}/tree`, `POST /runs/{id}/snapshots` | JSON сохранён, версия снимка записана |
| Протокол интервью и согласие | UI / `GET /runs/{id}/messages`, реестр согласий | Цитаты дословны, ПДн отсутствуют, согласие приложено |
| Источники | `GET /runs/{id}/sources` | ≥5, ≥3 типов, у каждого есть ID |
| Конфликты | `GET /runs/{id}/conflicts` | Победитель и причина у каждого |
| Сводка проверки | `GET /runs/{id}/review/summary` | Счётчики сходятся с деревом |
| Сопоставление и покрытие | `GET /runs/{id}/program-links`, `GET /runs/{id}/program-coverage` | ≥1 `proposed`, `program_id` совпадает |
| Журнал замечаний | [06-pilot-feedback.md](06-pilot-feedback.md) | Создан, статус **ОЖИДАЕТ ЗАМЕЧАНИЙ** |

**Приёмка передачи:** методист получил все строки таблицы и может открыть каждый
узел, цитату и связь без разработчика. Проверка обоснований и утверждение связей
— работа методиста после передачи; карточка 28 считается выполненной, когда пакет
полон и прогон завершён, а не когда все связи утверждены.

### Шаг 11. Закрыть прогон

1. Обновите статусы: карточка 28 — **ВЫПОЛНЕНО**, карточка 29 — **ОЖИДАЕТ
   ЗАМЕЧАНИЙ**.
2. Запишите длительность, стоимость (`GET /runs/{id}/cost`) и статус финализации
   в пакет.
3. Передайте журнал замечаний владельцу продукта и методисту; не закрывайте
   замечания «на месте» без триажа.

**Приёмка:** статусы обновлены, пакет полон, журнал открыт со статусом
**ОЖИДАЕТ ЗАМЕЧАНИЙ**.

## 4. Как понять, что шаг не удался

| Шаг | Признак | Вероятная причина | Что делать | Блокирует? |
|---|---|---|---|---|
| 1. Стенд | Соединение отклонено, `000`/таймаут | Backend не запущен, неверный `BaseUrl`, порт занят | Проверить процесс/порт/`docker compose`; не менять URL наугад | Да |
| 1. Стенд | `ready` 503 `not_ready`, `db_pool_unavailable`, `schema_not_ready` | Демо-API или миграции не применены | Запустить `cmd/server`, применить миграции; демо-режим не подходит | Да |

не ошибки сами по себе; они становятся замечанием, только если противоречат
данным или ожидаемому поведению.

## 5. Критерии приёмки прогона

- [ ] decision record подписан; `program_id`, псевдоним и согласие зафиксированы;
- [ ] `health` и `ready` — 200; использован `cmd/server` + PostgreSQL;
- [ ] исследование создано с `result_kind=program`, `stage=interview`;
- [ ] интервью: 2–3 случая, 3+ действия в каждом, 0 наводящих вопросов, 20–40 минут;
- [ ] финализация — `done` (не `degraded`/`failed`);
- [ ] дерево: 1 `role`, ≥2 `function`, ≥4 `task`, ≥8 `action`, у всех узлов есть обоснования;
- [ ] конфликты зафиксированы (в том числе пустой список), у каждого есть победитель и причина;
- [ ] `review/summary` сходится с деревом;
- [ ] сопоставление: ≥1 `proposed`, покрытие рассчитано, `program_id` совпадает;
- [ ] пакет передан методисту; журнал замечаний открыт со статусом **ОЖИДАЕТ ЗАМЕЧАНИЙ**;
- [ ] карточка 28 переведена в **ВЫПОЛНЕНО** только после этого.

## 6. Скрипт проверки

`scripts/pilot/run-scenario.ps1` проходит те же API-шаги и печатает чек-лист
`PASS/FAIL`; при любом `FAIL` завершается с кодом 1.

| Параметр | Обязателен | Назначение |
|---|---|---|
| `-BaseUrl` | Нет, по умолчанию `http://127.0.0.1:8080` | Адрес backend |
| `-Token` | Нет, берётся из `$env:MODEUS_TOKEN` | Bearer-токен; в файле не хранится |
| `-Profession` | Да, кроме `-DryRun` | Профессия из decision record |
| `-ProgramId` | Да, кроме `-DryRun` | `program_id` выбранной программы |
| `-TranscriptPath` | Нет | Файл ответов для replay (UTF-8, одна строка — один ответ) |
| `-DryRun` | Нет | Печать плана без сети, код 0 |

```powershell
# Офлайн-проверка плана, сеть не используется.
pwsh -NoProfile -File scripts/pilot/run-scenario.ps1 -DryRun `
  -Profession "Техник-механик" -ProgramId "00000000-0000-0000-0000-000000000000"

# Полный прогон; токен — только в окружении.
$env:MODEUS_TOKEN = "<admin-token>"
pwsh -NoProfile -File scripts/pilot/run-scenario.ps1 `
  -BaseUrl "http://127.0.0.1:8080" `
  -Profession "Техник-механик" `
  -ProgramId "<program_id>" `
  -TranscriptPath ".\pilot\interview-R-01.txt"
```

Коды выхода: `0` — все проверки PASS; `1` — есть FAIL; `2` — ошибка параметров
или отсутствует обязательный аргумент. Скрипт не проводит интервью за человека,
не утверждает обоснования и связи, не подписывает решение и не заменяет методиста.

Если PowerShell 7 (`pwsh`) не установлен, те же команды запускаются через
`powershell.exe -NoProfile -ExecutionPolicy Bypass -File ...`: скрипт совместим с
Windows PowerShell 5.1.

## 7. Остановка, эскалация, запреты

- **Стоп-правила:** нет подписи; не снят блокер ролей; `ready` не 200; нет
  согласия; интервью не дало случаев; финализация `failed`/`degraded`; покрытие
  пустое после генерации; любая ручная правка данных.
- **Кто решает:** владелец продукта — продолжать/остановить прогон; методист —
  достаточно ли материала и корректны ли уровни; ведущий прогона — технические
  остановки; владелец источников — дополнение данных.
- **Запрещено:** править БД и обходить API, чтобы «дособрать» дерево; выдавать
  `degraded` за `done`; закрывать замечание без триажа; хранить токен и ПДн в
  репозитории; проводить интервью без согласия.
- Любая остановка фиксируется в журнале замечаний с `run_id`, шагом, ожидаемым и
  фактическим поведением.
