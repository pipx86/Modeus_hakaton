# Что мы сделали, как это работает и почему так

Файл для команды, жюри и будущих участников: без технического жаргона.
Если коротко - мы сделали сервис, который **превращает разговор со
специалистом и документы о профессии в проверяемое дерево его работы**.

---

## 1. Зачем это нужно

Методисту вуза или колледжа надо понимать, **чем на самом деле занимается
специалист**, чтобы обновлять образовательную программу. Сегодня это делают
так: вручную берут интервью, читают вакансии и профстандарты, выписывают
функции и задачи в таблицу.

Проблемы этого пути:

- долго - один сильный разбор профессии занимает дни;
- субъективно - у каждого методиста своя формулировка;
- не видно оснований - «почему мы считаем, что это его задача?»;
- расхождения теряются - один сказал одно, другой другое, в итоге записали
  что-то среднее.

Мы автоматизировали сбор и оставили человеку главное - **проверку**.

---

## 2. Что делает продукт

1. Проводит **интервью в чате** со специалистом: агент спрашивает про роль,
   функции, задачи и конкретные действия.
2. Может использовать **готовые материалы**: вакансии, документы, стандарты.
3. Собирает из этого **дерево деятельности**:

   ```
   Роль: Аналитик данных
     Функция: Продуктовая аналитика
       Задача: Разобрать падение конверсии после релиза
         Действие: Построить разрез конверсии по платформам
   ```

4. У каждого элемента есть **основание** - дословная цитата из ответа человека
   или из документа. Без цитаты элемент не появляется.
5. Методист **проверяет** дерево: соглашается, отклоняет, правит название,
   оставляет комментарий.
6. Система **сопоставляет** дерево с образовательной программой и показывает,
   что подтверждено, что только предложено, а что осталось без связи.

---

## 3. Как это работает по шагам

```
Материалы (вакансии, документы)   +   Интервью со специалистом
                  \                       /
                   \                     /
              Аналитик: выделяет утверждения
              и находит цитату под каждое
                          |
                          v
              Синтезатор: сводит всё в одно дерево,
              сохраняет все цитаты, показывает разногласия
                          |
                          v
              Дерево в базе (с автоматическими проверками:
              один корень, правильные уровни, нет циклов)
                          |
                          v
              Методист проверяет -> сопоставление с программой
                          |
                          v
              Отчёт: что покрыто, что нет, что предложить
```

### Шаг 1. Создание исследования
Пользователь выбирает профессию и результат: только описание работы или ещё и
сопоставление с программой. Источники система подбирает сама - по профессии, из
уже обновляемой базы. Ничего вручную привязывать не нужно.

### Шаг 2. Интервью
Агент задаёт вопросы по четырём уровням и уточняет, если ответ общий. Отдельно
считается «качество ответа»: насколько он конкретный, есть ли личный вклад и
измеримый результат. Это подсказка интервьюеру, а не оценка человека.

### Шаг 3. Сборка дерева
Модель-аналитик выделяет утверждения и **обязана привести цитату** - фрагмент
текста, откуда это взято. Если цитаты нет, утверждение отбрасывается. Затем
синтезатор сводит несколько источников в одно дерево: одинаковое объединяет,
разное показывает как конфликт.

### Шаг 4. Проверка человеком
Методист проходит дерево: подтверждает, отклоняет, правит формулировки. Отдельно
видит конфликты - где источники спорят и на чём основан каждый вариант. Ничего
не пропадает: исходные цитаты остаются.

### Шаг 5. Программа
Система предлагает связи «элемент работы - компетенция программы». Методист
подтверждает, отклоняет или исправляет. Дальше строится отчёт о покрытии.

### Шаг 6. Результат
Всё лежит на одной странице исследования, откуда можно выгрузить отчёт или
распечатать. При повторном исследовании видно, что изменилось.

## 4. Почему мы сделали именно так

| Решение | Почему так |
|---|---|
| **Каждое утверждение подкреплено цитатой** | Модель нельзя ловить на словах, но можно проверить источник. Цитата делает вывод проверяемым, а не «мнение ИИ» |
| **Без цитаты утверждение не создаётся** | Лучше пропустить сомнительное, чем показать методисту выдумку |
| **Решение всегда за человеком** | Система не утверждает программу и не переписывает учебный план. Ответственность остаётся у вуза |
| **Разногласия показываем, а не прячем** | Если два источника расходятся, это ценная информация для методиста, а не помеха |
| **Четыре уровня: роль, функция, задача, действие** | Общий язык для интервьюера, модели и методиста. Иначе споры «это задача или действие?» съедают всё время |
| **Источники берём из существующей базы** | Мы не переделываем загрузку, парсинг и проверку данных - они живут отдельно и обновляются сами |
| **Связи с программой - предложения, а не факты** | Совпадение слов ничего не доказывает: решение принимает методист |
| **Падение анализа не смертельно** | Ответы человека - самый дорогой ресурс. Если модель упала, есть кнопка «Повторить анализ», ответы сохранены |
| **Снимки и история изменений** | Нужно уметь ответить: что изменилось с прошлого раза и почему |
| **Одна страница на всё** | Методисту неудобно прыгать по разделам: источники, дерево, интервью, программа - рядом |

## 5. Что уже сделано

| Этап | Карточки | Что сделано простыми словами |
|---|---|---|
| Договорились о результате | 1-3 | Описали, что получает методист, что такое уровни дерева и выбрали пилот |
| Проверили данные | 4-5 | Сделали команду аудита: она заранее говорит, каких материалов и данных программы не хватает |
| Научили систему брать материалы | 6-10 | Выводы с цитатами, подбор по профессии, разногласия, экран использованных материалов |
| Сделали интервью | 11-15 | Сценарий, несколько респондентов, правила для агента, экран интервью, ответы как основания |
| Собрали дерево | 16-19 | Единый формат, сборка с сохранением цитат, проверка узлов, сравнение версий |
| Добавили программу | 20-24 | Связи с компетенциями, предложения, экран проверки, отчёт о покрытии |
| Связали интерфейс | 25-29 | Выбор результата, единая страница, эталон для проверки, инструкция пилота, сбор замечаний |
| Сделали сверх плана | 30-32 | Отслеживание изменений материалов, отчёт об изменениях деятельности, предложения по программе |
| Отложили | 33-34 | Личные планы студента и аватар интервьюера - сначала проверим обычный чат |

Отдельно, хотя этого не было в карточках: **повтор анализа после падения**,
**команда для демонстрации полного интервью**, **три демо-учётки** (админ,
специалист, пользователь) и чистка интерфейса от технических деталей.

## 6. Что осталось людям (и почему это нельзя закодировать)

| Что | Почему ждёт человека |
|---|---|
| Подписать решение по пилоту (карточка 2) | Это организационное решение: какую профессию и программу показываем |
| Проверить ручной эталон (27) | Нужен взгляд эксперта: правильные ли формулировки, а не только формат файла |
| Провести пилот с живым специалистом (28) | Нужен реальный человек и его ответы, а не тестовые данные |
| Собрать замечания (29) | Появляются только после пилота |

---

## 7. Что проверено

- около **300 автоматических тестов** интерфейса и **200+ тестовых файлов** на
  сервере, включая проверки на гонки;
- линтеры, проверка типов и сборка идут в автоматическом конвейере;
- живой прогон: 5 ответов -> дерево из **14 узлов** и **14 цитат**;
- падение анализа воспроизводили: кнопка «Повторить анализ» возвращает дерево.

## 8. Как посмотреть

```bash
docker compose up -d postgres migrate
go run ./cmd/server                       # сервер на http://127.0.0.1:8080
cd frontend && npm ci && npm run dev      # интерфейс на http://127.0.0.1:5173
```

Демо-учётки (создаются командой `go run ./cmd/seed-demo-users`):

| Логин | Пароль | Роль |
|---|---|---|
| `admin@modeus.local` | `Admin12345` | администратор |
| `specialist@modeus.local` | `User12345` | специалист |
| `user@modeus.local` | `User12345` | пользователь |

Полный прогон интервью без ручного ввода: `go run ./cmd/interview-replay`.

## 9. Словарь

| Слово | Что это простыми словами |
|---|---|
| **Дерево деятельности** | Схема работы специалиста: роль, под ней функции, под ними задачи, внизу конкретные действия |
| **Узел** | Один элемент дерева - например, задача «Разобрать падение конверсии» |
| **Основание** | Цитата, из которой видно, откуда взялся узел |
| **Конфликт** | Место, где два источника говорят разное; система показывает оба варианта |
| **Снимок** | Сохранённая копия дерева на момент времени, чтобы сравнивать версии |
| **Покрытие программы** | Какие элементы работы уже связаны с программой, а какие нет |
| **Связь** | Пара «что делает специалист - чему это соответствует в программе» |
