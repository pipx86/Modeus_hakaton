# Карточка 2. Выбрать пилотную профессию, программу и специалиста

**Статус:** черновик · **решение не принято** · **требует подтверждения** владельцем продукта, методистом и владельцем источников · карточка 2 плана MVP.

Карточка задаёт форму решения и критерии выбора. Она не выбирает пилот за команду: все поля ниже заполняются только после проверки и подтверждения. Рекомендация в разделе 3 — предложение, а не решение.

## 1. Форма записи решения (decision record)

| Поле | Значение | Статус |
|---|---|---|
| ID и версия записи | `<MVP-PILOT-01>`, версия `<...>`, дата `<...>` | Требует заполнения |
| Владелец решения | `<роль/ФИО>`; согласуют: методист `<...>`, владелец источников `<...>` | Требует подтверждения |
| Профессия / роль | `<название профессии и роли>`; границы: `<организация/отрасль/уровень>` | **Не выбрано**, требует подтверждения |
| Образовательная программа | `<название программы>`; уровень образования: `<СПО / ВО / ДПО>`; код: `<...>`; версия и дата: `<...>`; документ-источник: `<...>` | **Не выбрано**, требует подтверждения |
| Уровень сопоставления | MVP: **компетенции и KSA**. Дисциплины и результаты обучения — **не реализовано**: в схеме нет отдельных таблиц, их можно хранить только как текст источника | Требует подтверждения |
| Респондент | `<псевдоним>`; роль и стаж: `<...>`; как найден: `<канал, кто нашёл, дата>`; согласие: `<есть/нет>`; резервный респондент: `<...>` | **Не выбран**, требует подтверждения |
| Источники по профессии | Проверенный набор: `<N>` источников, `<типы>`; идентификаторы: `<...>`; см. чек-лист в разделе 4 | Требует проверки |
| Объём сопоставления для MVP | 1 программа; 3–5 компетенций; 5–10 KSA; 5–8 узлов уровня task/action; не более одного предложения сопоставления на узел | Предложение, требует подтверждения |
| Вне MVP | Полное покрытие дерева; дисциплины и результаты обучения; автоматическое изменение программы; несколько программ одновременно | Зафиксировать при решении |
| Решение | `<выбран вариант / отложено / отклонено>`; дата и подписи | **Не принято** |

Персональные данные респондента (ФИО, контакты) в этот файл не записываются: в документе остаётся псевдоним и ссылка на защищённый реестр.

## 2. Критерии выбора профессии

| Критерий | Проверка | Порог для MVP | Статус |
|---|---|---|---|
| Есть реальный практик | Согласие на интервью и уточняющие вопросы; доступность 60–90 минут | 1 основной респондент; резервный — желательно | Проверить |
| Есть база источников | Разные типы материалов, не только вакансии | **N = 5 источников, минимум 3 типа**, обязательно ≥1 интервью и ≥1 профстандарт или документ | Предложение, требует подтверждения |
| Деятельность наблюдаема | Можно назвать артефакты, инструменты и результат шага | Не менее 2 функций, 4 задач и 8 действий в первом прогоне | Проверить на пробном дереве |
| Уровни различимы | Есть задачи, которые раскрываются в действия, а не одна сплошная формулировка | 2–3 спорных случая для калибровки карточки 3 | Проверить |
| Программа реально сопоставима | В программе есть компетенции и KSA, близкие к деятельности | 3–5 релевантных компетенций, 5–10 KSA | Проверить |
| Не только IT | Профессия не входит в три разрешённые промптами роли | Обязательное условие пилота | Проверить |
| Нет запрета на данные | Материалы можно обезличить и использовать внутри проекта | Согласие/правовое основание есть | Проверить |
| Актуальность | Вакансии не старше 12 месяцев; стандарт действующий; интервью о текущей практике; документ — действующей версии | Все источники проходят | Проверить |

Требование «не только IT» нужно, чтобы проверить универсальность уровней и промптов. Пилот на аналитике данных, DevOps-инженере или backend-разработчике не отвечает на вопрос, работает ли система за пределами трёх зашитых ролей.

## 3. Три варианта выбора

| Вариант | Профессия — пример типа роли | Программа и уровень | Плюсы | Минусы и условия |
|---|---|---|---|---|
| **A. Не-IT, производственно-техническая** | Оператор станка с ЧПУ / техник-механик | `<программа СПО>`, компетенции и KSA | Деятельность наблюдаема; действия конкретны; обычно есть профстандарт и вакансии; проверяет универсальность | Нужен доступ к практику и программе; промпты придётся расширить; часть цитат может быть только из документов |
| **B. Не-IT, сервисно-гуманитарная** | Медицинская сестра / специалист по социальной работе | `<программа СПО или ВО>`, компетенции и KSA | Богатая практика; типовые задачи и действия; сильные программы с компетенциями | Персональные данные и этика; согласования; риск чувствительных формулировок; нужен безопасный протокол интервью |
| **C. IT вне трёх разрешённых ролей** | QA-инженер / системный аналитик | `<программа ВО или ДПО>`, компетенции и KSA | Источники доступны; команде легко проверить; тестирует технический долг промптов | Не проверяет универсальность за пределами IT; риск экспертной предвзятости; без снятия ограничения промптов система не обработает роль |

**Рекомендация (предложение, не решение): вариант A.** Он даёт наибольшую методическую ценность: проверяет не-IT деятельность, разные уровни и реальную сопоставимость программы. Рекомендация действует только при трёх условиях: подтверждён практик, программа содержит 3–5 релевантных компетенций/KSA, а промпты поддерживают выбранную роль. Если практик или программа недоступны, вариант B допустим только после решения вопросов данных и этики; вариант C — техническая проверка, а не пилот универсальности.

Решение принимает владелец продукта по согласованию с методистом. До этого поля decision record остаются «не выбрано», а рекомендация — «предложение».

## 4. Чек-лист проверки источников

| ✓ | Проверка | Критерий |
|---|---|---|
| ☐ | Тип источника | Ровно один из `interview`, `standard`, `vacancy`, `document`; другого типа нет. Наблюдение загружается как `document` или включается в интервью |
| ☐ | Текст | Текст полный, не обрезан, читается; для цитаты доступен исходный фрагмент |
| ☐ | Дата | Указана дата материала: для вакансии — публикации, для интервью — разговора, для документа — версии. Если дата не хранится отдельно, она должна быть зафиксирована в названии/карточке источника |
| ☐ | Ссылка или идентификатор | Есть `source_url` либо `provider` + `external_id`; для интервью — идентификатор сообщения (`ref_id`) |
| ☐ | Техническая валидация | В системе есть проверка наличия текста, происхождения, формата URL и совпадения цитаты. Она не подтверждает смысл и достоверность источника |
| ☐ | Найден анализатором | Контрольный запрос по ключевой фразе находит источник; анализатор может построить на нём обоснование |
| ☐ | Нет дублей | Один и тот же материал не загружен дважды под разными названиями |
| ☐ | Права и обезличивание | Нет запрещённых персональных данных; согласие или правовое основание зафиксированы |

Набор источников принимается, только если одновременно:

- [ ] всего не менее 5 источников;
- [ ] не менее 3 типов;
- [ ] есть минимум 1 интервью;
- [ ] есть минимум 1 профстандарт или документ;
- [ ] у каждого источника пройдены все проверки выше;
- [ ] ключевые факты, подтверждённые единственным источником, должны быть помечены как риск, а не выданы за проверенные.

## 5. Чек-лист проверки данных программы

- [ ] программа найдена в справочнике и однозначно идентифицируется по названию, организации и коду;
- [ ] зафиксированы версия/год и документ-основание; старая и новая версии не смешаны;
- [ ] компетенции загружены: не менее 3 релевантных, с кодами и формулировками;
- [ ] KSA загружены: не менее 5 на выбранный фрагмент, типы только `knowledge`, `skill`, `ability`;
- [ ] проверено, что KSA не являются пустыми или дублирующими друг друга;
- [ ] программа не менялась после выбора; повторный импорт не создал дублей;
- [ ] уровень MVP зафиксирован: только компетенции и KSA. Дисциплины и результаты обучения не сопоставляются структурно — **не реализовано**;
- [ ] владелец программы подтвердил, что программу можно использовать в пилоте и что сопоставление будет предложением, а не изменением;
- [ ] в decision record записаны ID программы и выбранных компетенций.

Если в программе меньше 3 релевантных компетенций или нет KSA, объём MVP уменьшается до сопоставления на уровне компетенций; это фиксируется как ограничение пилота и не выдаётся за полное сопоставление. Сама функция сопоставления при этом остаётся нереализованной до направления D.

## 6. Критерий готовности карточки

**Документ готов к решению**, когда:

- [ ] decision record заполнен по всем полям, кроме тех, что сознательно оставлены «не выбрано»;
- [ ] три варианта оценены по критериям, у рекомендации явно стоит «предложение»;
- [ ] чек-листы источников и программы заполнены на конкретных данных, а не на примерах;
- [ ] зафиксированы объём сопоставления и ограничения MVP;
- [ ] документ отправлен на согласование владельцу продукта и методисту.

**Пилот можно запускать**, когда дополнительно:

- [ ] решение по профессии, программе и респонденту подтверждено и подписано;
- [ ] основной респондент дал согласие и доступен по срокам;
- [ ] набор из 5 источников и данные программы прошли чек-листы;
- [ ] промпты поддерживают выбранную роль (текущее ограничение трёх IT-ролей снято или роль входит в разрешённые);
- [ ] назначен методист, который пройдёт дерево и проверит обоснования.

До выполнения второго блока карточка считается готовой только как форма решения, но не как разрешение на пилот.
