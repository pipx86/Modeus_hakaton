# LLM-адаптер ФГОС: компетенции из PDF, DOCX и HTML

Как система извлекает компетенции и KSA из документов ФГОС, какие ограничения
у этого способа, как включить адаптер и как проверить его без реальной модели.

## Зачем

Вузовские программы и ФГОС приходят в PDF и DOCX. Детерминированного парсера
для них нет: компетенции в документе свёрстаны таблицами и списками, а не
размечены как CSV/XLSX. Поэтому текст разбирает LLM: она возвращает структуру
`{code, title, type, ksa, citations}` и обязана подтверждать каждый пункт
дословной цитатой с номером страницы. Результат — обычный черновик импорта:
методист проверяет его и публикует тем же эндпоинтом, что и файл из админки.

Отдельный случай — официальные стандарты на fgosvo.ru: сам ФГОС выложен сканом
без текстового слоя, а полный текст приказа лежит на обычной HTML-странице
(например, `https://www.fgosvo.ru/news/view/3224`). OCR такого скана теряет
часть компетенций, поэтому воркер сначала смотрит на текст HTML-страницы и
разбирает его напрямую, а к PDF/OCR возвращается, только если текста стандарта
в HTML нет.

Перед отправкой модели документ фильтруется: уходят только страницы раздела
компетенций и KSA, а общие положения, структура программы и требования к
условиям реализации не тратят токены и время.

## Как работает

```
PDF/DOCX ──► ExtractPages ──► страницы ──► отбор раздела компетенций
HTML ──────► HTMLText/PagesFromHTML ──► страницы ──► (тот же путь)
                                              │
                                              ▼
                                     чанки по ~6 000 символов
                                              │
                                              ▼
                                     промпт prompts/fgos/v1/system.md
                                              │
                        ┌─────────────────────┴─────────────────────┐
                        ▼                                           ▼
                 JSON от модели                             413 / context / таймаут /
                        │                                  невалидный или пустой JSON
                        │                                           │
                        │                                           ▼
                        │                            деление чанка пополам (≤4 уровней,
                        │                            до 1500 символов) и повтор
                        ▼
              валидация пунктов ──► дедуп по коду ──► EducationProgram
                                              │
                                              ▼
                                   черновик импорта (warnings)
```

1. **Страницы.** `fgos.ExtractPages` режет документ на страницы:
   - PDF — по дереву страниц библиотеки `ledongthuc/pdf`, номера точные;
   - DOCX — по разрывам `w:br w:type="page"`, `w:lastRenderedPageBreak` и
     `w:pageBreakBefore`. Нумерация приблизительная: Word расставляет разрывы
     при вёрстке. Для DOCX в черновик добавляется предупреждение
     «номера страниц приблизительные…»;
   - скан без текстового слоя — OCR, если он включён (см.
     [14-ocr.md](14-ocr.md)); иначе ошибка «нет текстового слоя, нужен OCR»;
   - HTML-страница — если в тексте есть признаки ФГОС, разметка вычищается, а
     текст режется на условные страницы по ~3000 символов (см.
     [«HTML-режим»](#html-режим-текст-стандарта-вместо-скана)). Для HTML в
     черновик добавляется предупреждение «номера страниц из HTML условные».
2. **Отбор раздела компетенций.** Перед чанкованием
   `fgos.SelectCompetencyPages` оставляет только страницы, где есть
   компетенции и KSA:
   - признаки страницы: «компетенц», коды `УК-` / `ОПК-` / `ПК-`, «знать»,
     «уметь», «владеть», «требования к результатам освоения», а также
     «профессиональн» вместе с «компетенц»;
   - к найденным страницам добавляется окно соседних страниц
     (`FGOS_SECTION_WINDOW`, по умолчанию 1): страница-продолжение таблицы
     может не повторять заголовок раздела, но содержит строки с кодами;
   - если признаков нет ни на одной странице, документ обрабатывается целиком,
     а в черновик попадает предупреждение «раздел компетенций не найден,
     обрабатывается весь документ»;
   - если отобрано больше 60% страниц и хотя бы одна страница отброшена,
     результат не меняется, но добавляется предупреждение «отобрано N из M
     страниц» — экономии почти нет;
   - потолок отбора — 80 страниц; `MaxPages` проверяется уже по отобранным
     страницам, поэтому общие положения не упираются в лимит.

   При реальном отборе в черновик добавляется «обработано N из M страниц:
   только раздел компетенций», а в лог — событие `fgos_section_selected` с
   полями `pages_total`, `pages_selected`, `window`, `section_only`. Отключить
   отбор можно переменной `FGOS_SECTION_ONLY=false`.
3. **Чанки.** Страницы режутся на фрагменты по `MaxCharsPerChunk` (по умолчанию
   6 000 символов: модели с небольшим контекстом отвечают 413 на длинный
   запрос). На этом этапе страница не разрывается — цитата проверяется по
   целому тексту страницы; страница длиннее лимита становится отдельным чанком.
4. **Аварийное деление.** Если модель ответила 413 / context length / таймаутом
   или вернула невалидный либо пустой JSON, чанк делится примерно пополам, и
   запрос повторяется. Деление рекурсивное: не более 4 уровней (максимум
   1+2+4+8+16 запросов на один чанк) и не меньше 1500 символов. Результаты
   подзапросов объединяются по коду компетенции. В черновик добавляется
   предупреждение **«чанк уменьшен из-за лимита модели»**, а в лог — событие
   `fgos_chunk_split` с размером чанка, размерами половин и причиной деления
   (успешные запросы видны как `fgos_chunk_request`).
5. **Промпт.** На каждый чанк уходит системный промпт `prompts/fgos/v1/system.md`
   и пользовательское сообщение со страницами и требованием вернуть JSON. Промпт
   требует извлекать **только компетенции и KSA** и явно велит игнорировать
   общие положения, структуру программы, требования к условиям реализации,
   кадры и материально-техническое обеспечение, а также не выдумывать
   компетенции, которых нет в тексте:

   ```json
   {"competencies":[{"code":"УК-1","title":"...","type":"universal",
     "ksa":[{"kind":"knowledge","title":"..."}],
     "citations":[{"page":3,"quote":"дословный фрагмент"}]}]}
   ```
6. **Валидация.** Пункт остаётся, только если:
   - `code` соответствует `^[А-ЯЁ]{2,4}-\d+$` (`УК-1`, `ОПК-2`, `ПК-3`);
   - `title` не пустой;
   - `type` приводится к `universal` / `general_professional` / `professional` /
     `other` (русские `УК` / `ОПК` / `ПК` / `иное` маппятся);
   - `ksa[].kind` приводится к `knowledge` / `skill` / `ability`
     (`знание` / `умение` / `навык`);
   - в `citations` есть хотя бы одна цитата, которая подтверждается на
     указанной странице или в пределах `FGOS_CITATION_WINDOW` соседних страниц
     документа (по умолчанию ±1, `0` отключает окно).

   Сравнение цитаты мягкое: `NormalizeForQuote` удаляет мягкий дефис `\u00ad`,
   склеивает перенос слова `-\n` / `-\r\n`, схлопывает все виды пробелов
   (включая `\u00a0` и табы), приводит регистр и заменяет `ё` на `е`. Сами
   цитаты при этом сохраняются как есть — нормализация существует только для
   сравнения. Цитаты короче 20 символов проверяются точным вхождением без
   нормализации: после схлопывания пробелов такие строки совпадают слишком
   легко.

   Цитата, найденная на соседней странице, принимается без предупреждения:
   модель иногда указывает страницу, на которой начинается пункт, а сама
   формулировка уезжает на следующую. Если цитата не нашлась, в `warnings`
   попадает причина «не найдена на странице N ± window»; невалидные пункты и
   отдельные цитаты отбрасываются. Ответ модели, обёрнутый в markdown-блок,
   разбирается; невалидный JSON даёт предупреждение и попытку деления, а не
   падение.
7. **Ответ модели.** `MaxResponseTokens` (по умолчанию 4000) ограничивает
   размер ответа. Если клиент реализует `SetMaxResponseTokens`, лимит
   передаётся провайдеру; кроме того, адаптер сам считает ответ длиннее
   `4 × MaxResponseTokens` символов ошибкой и делит чанк. Провайдерный лимит
   по-прежнему задаётся `LLM_ANALYST_MAX_TOKENS`.
8. **Дедуп.** Компетенции объединяются по `code`: KSA складываются, при разных
   формулировках остаётся первая и добавляется предупреждение о конфликте.
9. **Пустой результат.** Если после всех чанков и всех попыток деления не
   осталось ни одной компетенции, ошибка оборачивает «не удалось извлечь
   компетенции» и содержит причину последней неудачи — например,
   `upstream returned status 413` или `невалидный JSON: ...`. Общего текста без
   причины больше нет.

## HTML-режим: текст стандарта вместо скана

На fgosvo.ru сам ФГОС часто выложен сканом без текстового слоя — OCR теряет
часть компетенций (на пилотном стандарте нашлось 10 из 17), а на том же портале
обычно есть HTML-страница с полным текстом приказа, например
`https://www.fgosvo.ru/news/view/3224`. Поэтому воркер и ручная проверка
источника сначала смотрят на HTML.

Как это работает:

1. Если источник ответил HTML, `programwatch.HTMLText` вырезает `script`,
   `style`, `noscript`, `template`, комментарии и теги, декодирует
   HTML-сущности (`html.UnescapeString`: `&nbsp;` → пробел, `&laquo;` → «) и
   схлопывает пустые строки.
2. `LooksLikeFGOS` решает, похож ли текст на стандарт: не меньше трёх кодов
   `УК-` / `ОПК-` / `ПК-` (допускаются пробелы и разные тире) либо одновременно
   слова «компетенц» и «требования к результатам». Обычная новость или
   страница со ссылкой на PDF этот тест не проходят.
3. Если текст похож на ФГОС, ссылка на PDF не ищется: HTML приоритетнее
   документа. `PagesFromHTML` режет текст на условные страницы по ~3000
   символов, не разрывая абзац (абзац длиннее страницы делится по словам), и
   текст уходит в тот же LLM-адаптер через `ExtractFromPages`. Черновик
   создаётся как обычно, но с `source_format=html`, `source_name` = host+path
   страницы (например, `www.fgosvo.ru/news/view/3224`) и предупреждением
   «номера страниц из HTML условные».
4. Если текст не похож на ФГОС или `FGOS_HTML_TEXT=false`, поведение прежнее:
   на странице ищется ссылка на документ, PDF/DOCX разбирается адаптером.
5. Если LLM-адаптер не настроен, HTML с текстом ФГОС даёт `needs_parser` без
   черновика — так же, как PDF.
6. Неизменившаяся HTML-страница (тот же `last_hash`) повторно не разбирается:
   второй черновик из того же текста не создаётся.

Номера страниц в HTML-режиме условные: страница — это порция текста, а не лист
документа. Цитата всё равно проверяется по этой порции и соседним
(±`FGOS_CITATION_WINDOW`), поэтому перенос абзаца через границу условной
страницы не теряет компетенцию, но сверять черновик с бумажным оригиналом
нужно по тексту, а не по номерам листов.

## Где используется

| Место | Поведение |
|---|---|
| `cmd/program-watcher -pdf-llm` | Проверяет источник: HTML-текст ФГОС разбирает без скачивания PDF, PDF/DOCX — через адаптер; при успехе создаёт черновик, статус `changed`. Без флага (или без настроенной LLM) — `needs_parser`. |
| `POST /api/v1/admin/programs/import` | PDF/DOCX разбираются синхронно (бюджет `PROGRAM_IMPORT_TIMEOUT_S`, по умолчанию 15 минут; общий для LLM и OCR) и создают черновик. Без адаптера — 422 `PROGRAM_IMPORT_LLM_NOT_CONFIGURED`; если модель недоступна или не ответила за отведённое время — 503. HTML-режим относится к проверке источников, а не к загрузке файла. |
| `POST /api/v1/admin/program-sources/{id}/check` | Ручная проверка использует тот же адаптер и тот же HTML-режим, если адаптер настроен на сервере. |

## Как включить

Адаптер использует существующий LLM-клиент проекта (`internal/llm`), поэтому
настраивается теми же переменными окружения, что и остальные агенты:

```bash
export LLM_API_KEY=...            # или LLM_API_KEY_FILE / .secrets/reformboss.key
export LLM_BASE_URL=https://api.reformboss.com/v1   # по умолчанию
export LLM_MODEL=deepseek-v4.1-flash-1017           # модель по умолчанию
# опционально, отдельная модель и бюджет для аналитика:
export LLM_ANALYST_MODEL=...
export LLM_ANALYST_TIMEOUT_S=300
export LLM_TIMEOUT_S=300

# отбор только раздела компетенций (по умолчанию включён):
export FGOS_SECTION_ONLY=true
# сколько соседних страниц добавлять к найденным (0 отключает окно):
export FGOS_SECTION_WINDOW=1

# HTML-режим: брать текст ФГОС прямо со страницы (по умолчанию включён).
# false — прежнее поведение: искать на странице ссылку на PDF/DOCX:
export FGOS_HTML_TEXT=true
# сколько соседних страниц проверять при сверке цитаты (0 — только указанная):
export FGOS_CITATION_WINDOW=1
```

**cmd/server** включает адаптер автоматически, если настроен analyst-клиент
(в логе появляется `program_import_llm_adapter_enabled`). Если LLM не настроен,
импорт PDF/DOCX отвечает 422, а сервер продолжает работать.

**cmd/program-watcher** включает адаптер флагом:

```bash
go run ./cmd/program-watcher -once -pdf-llm
```

Если LLM не настроен, воркер пишет `fgos_llm_not_configured` и продолжает
работать без адаптера: PDF/DOCX (и HTML-страница с текстом ФГОС) остаются в
статусе `needs_parser`, остальные форматы проверяются как раньше. HTML-режим
включается переменной `FGOS_HTML_TEXT` (по умолчанию `true`), а не отдельным
флагом: он использует тот же `PDFExtractor`, что и PDF/DOCX.

Ограничения запуска задаются полями `fgos.Extractor`: `MaxPages` (по умолчанию
80), `MaxCharsPerChunk` (6 000), `MaxResponseTokens` (4 000), `Timeout`
(5 минут в самом адаптере). `cmd/server` выставляет `Timeout` равным
`PROGRAM_IMPORT_TIMEOUT_S` (по умолчанию 15 минут); при отказе модели чанк
делится автоматически, поэтому уменьшать `MaxCharsPerChunk` вручную нужно
только для очень «капризного» провайдера. `cmd/program-watcher` использует
значения по умолчанию; lease-блокировка источника (20 минут по умолчанию)
больше таймаута разбора. `MaxPages` проверяется после отбора: если раздел
компетенций занимает 10 страниц из 100, документ проходит при лимите 80.

### Когда отключать отбор

Отбор включён по умолчанию: это обычный случай, когда ФГОС состоит из общих
положений, структуры программы и требований к условиям реализации, а
компетенции занимают несколько страниц. Если маркеры не находятся ни на одной
странице, отбор сам возвращает весь документ с предупреждением — отключать его
для этого не нужно. `FGOS_SECTION_ONLY=false` имеет смысл, если:

- нужно извлечь компетенции из приложения или таблицы, которая не содержит слов
  «компетенции», «знать», «уметь», «владеть» и кодов `УК-` / `ОПК-` / `ПК-`, но
  маркеры нашлись на других, не относящихся к делу страницах;
- отбор ошибочно выбросил страницу, которую методист считает частью раздела:
  проверьте `report.warnings` и событие `fgos_section_selected` в логе, затем
  либо увеличьте `FGOS_SECTION_WINDOW` (например, до 2), либо отключите отбор
  для этого запуска.

`FGOS_SECTION_WINDOW=0` оставляет только страницы с маркерами — полезно, когда
таблицы компетенций плотные и соседние страницы содержат лишний текст.
Увеличение окна повышает полноту, но снижает экономию.

## Как проверить без реальной LLM

Сеть и модель в тестах не нужны:

```bash
# адаптер: чанки, JSON, отбраковка, дедуп, таймаут, MaxPages, страницы PDF/DOCX
go test -count=1 ./internal/fgos/

# цитаты: нормализация, мягкие дефисы/переносы/пробелы, окно соседних страниц
go test -count=1 -run 'Quote|NormalizeForQuote|CitationWindow' ./internal/fgos/

# отбор раздела: маркеры, окно, 2 из 10 страниц, fallback, MaxPages, env
go test -count=1 -run 'Select|Section' ./internal/fgos/

# аварийное деление чанков: 413, рекурсия, лимит глубины, объединение, текст ошибки
go test -count=1 -run 'TestExtractSplits|TestExtractSplitDepthLimit|TestExtractOversizedResponse|TestExtractLLMErrorReason' ./internal/fgos/

# чекер с фейковым PDF-экстрактором создаёт черновик
go test -count=1 -run 'PDF|DOCX' ./internal/programwatch/

# HTML-режим: теги/скрипты/сущности, LooksLikeFGOS, условные страницы,
# приоритет над PDF-ссылкой, FGOS_HTML_TEXT=false, fallback на PDF
go test -count=1 -run 'HTML|LooksLikeFGOS|PagesFromHTML' ./internal/programwatch/

# импорт PDF/DOCX через endpoint с фейковым адаптером
go test -count=1 -run 'TestProgramImportPDF|TestProgramImportDOCX' ./internal/api/
```

В тестах используются два уровня подмены:

- `internal/fgos` — `fakeLLM` реализует `llm.ChatClient` и возвращает заранее
  заданный JSON или ошибку по тексту запроса, поэтому проверяются чанки,
  рекурсивное деление и валидация без сети;
- `internal/programwatch` и `internal/api` — фейковый `fgos.DocumentExtractor`
  (интерфейс `ExtractPages` + `Extract`, у HTML-тестов ещё и необязательный
  `ExtractFromPages`) возвращает страницы и программу, поэтому не нужен
  настоящий PDF с текстом.

Проверка «вживую» без платного провайдера: укажите `LLM_BASE_URL` на локальный
OpenAI-совместимый сервер (LM Studio, llama.cpp server и т. п.) и любой
`LLM_API_KEY`. Для быстрой проверки одного документа:

```bash
curl -s -X POST http://127.0.0.1:8080/api/v1/admin/programs/import \
  -H "Authorization: Bearer $TOKEN" \
  -F "key=mirea/09.03.01/2024/full-time" \
  -F "file=@fgos.pdf"
```

Ответ 201 содержит `draft_id`, программу и `report.warnings`; черновик виден в
`GET /api/v1/admin/programs/drafts/{id}`.

## Стоимость

Платит провайдер LLM за токены. Стоимость считается только по тем страницам,
которые реально ушли модели, поэтому отбор раздела компетенций — главный
рычаг экономии и времени:

- один чанк ≈ 6 000 символов ≈ 2–3 тыс. токенов входа вместе с промптом;
- типовой ФГОС на 40–60 страниц — это ≈ 150–250 тыс. символов и 25–40
  запросов без отбора; раздел компетенций занимает обычно 5–15 страниц, то есть
  4–10 чанков. Время разбора падает примерно во столько же раз;
- документ на 10 страниц раньше уходил в модель целиком (≈6 минут); после
  отбора это обычно 2–4 страницы (2–4 чанка) и 1–2 минуты, если не нужен OCR и
  модель не делит чанки;
- ответ модели — 0.5–1.5 тыс. токенов на чанк (структура с цитатами);
- при отказе модели чанк делится, поэтому число запросов (и стоимость) может
  вырасти в 2–7 раз на «проблемных» фрагментах.

При цене провайдера, например, $0.5 за 1M входных и $1.5 за 1M выходных токенов,
документ без отбора стоит примерно **$0.08–0.15**, а с отбором раздела —
обычно **$0.02–0.05** (с запасом на деление чанков). Если раздел занимает
больше 60% страниц, экономия невелика — об этом предупреждает «отобрано N из M
страниц». Стоимость дополнительно ограничивают `MaxPages` (после отбора) и
бюджет импорта `PROGRAM_IMPORT_TIMEOUT_S` (15 минут) / `Timeout` адаптера: при
превышении возвращается ошибка, а не бесконечный расход. Повторная проверка
источника не тратит токены, если не изменились `last_hash` страницы
(HTML-режим) или `document_hash`/304 документа.

## Ограничения

1. **Качество зависит от модели и требует проверки человеком.** Дословность
   цитат проверяется детерминированно, но `title` и формулировки KSA — это ответ
   модели; методист обязан сверить черновик с документом до публикации.
2. **Сканы — через OCR, но сначала проверяется HTML.** PDF без текстового слоя
   и PNG/JPEG распознаются tesseract при `OCR_ENABLED=true` (см.
   [14-ocr.md](14-ocr.md)); точность ниже, а в предупреждениях появляется
   «страница N распознана OCR». Без OCR скан возвращает «нет текстового слоя,
   нужен OCR». Для официальных стандартов HTML-версия приоритетнее скана: она
   сохраняет компетенции дословно. DOCX не хранит постраничное разбиение: номера
   страниц приблизительные, а сложные таблицы и колонки могут потерять порядок
   текста.
3. **Извлекаются только компетенции и KSA.** Название программы берётся из имени
   файла (его можно исправить в черновике), организация и код программы не
   извлекаются. Коды принимаются только по шаблону `УК-1`/`ОПК-2`/`ПК-3`:
   коды с точками (`ПК-1.1`) или нестандартные обозначения отбрасываются с
   предупреждением.
4. **Отбор раздела — эвристика.** Признаки ищутся по тексту страницы, а не по
   структуре документа, поэтому в нестандартной вёрстке раздел может не
   найтись (тогда обрабатывается весь документ с предупреждением) или
   захватить лишнюю страницу. `FGOS_SECTION_WINDOW` расширяет окно, если
   страница-продолжение таблицы потерялась, а `FGOS_SECTION_ONLY=false`
   отключает отбор полностью. Если отобрано больше 60% страниц, экономия мала —
   в черновике появляется «отобрано N из M страниц».
5. **Чанки ограничивают контекст.** Компетенция, размазанная по разным чанкам,
   объединяется по коду, но KSA из другого чанка может потеряться; при конфликте
   формулировок остаётся первая. Документы, где после отбора остаётся больше
   80 страниц, отклоняются целиком, чтобы не платить за разбор, который
   закончится таймаутом.
6. **Синхронный импорт.** HTTP-запрос импорта ждёт разбор до
   `PROGRAM_IMPORT_TIMEOUT_S` (по умолчанию 15 минут); для больших стандартов
   лучше загружать CSV/XLSX или разбирать PDF воркером.
   Аварийное деление чанков увеличивает число запросов: на документе, где модель
   стабильно отвечает 413, разбор может упереться в таймаут раньше, чем закончится.
7. **HTML-режим зависит от полноты страницы.** Разбор включается, только если
   HTML действительно содержит текст стандарта; сокращённая новость, анонс или
   страница со ссылкой на PDF проходят мимо, и тогда работает прежний путь
   (документ + OCR). Номера страниц в HTML условные (порции по ~3000 символов),
   поэтому цитаты и `report.warnings` нужно сверять с текстом, а не с листами
   PDF; мягкая нормализация цитат (переносы, `ё`, пробелы) может скрыть редкие
   расхождения OCR-текста, если он всё же использовался.

## Проверка на реальном ФГОС 09.03.01

Источник: официальный портал fgosvo.ru, страница с текстом приказа № 929
(https://www.fgosvo.ru/news/view/3224), ключ `fgos/09.03.01/2017/full-time`.

| Режим | Время | Компетенций | Предупреждений |
|---|---:|---:|---:|
| PDF-скан с pravo.gov.ru, OCR | 271,7 с | 10 из 17 | 54 |
| HTML-страница, модель minimax | 94,6 с | **17 из 17** | 10 |
| HTML-страница, модель deepseek | **56,9 с** | **17 из 17** | 10 |

Вывод: HTML-режим снимает потери OCR, а deepseek на этом документе быстрее
minimax при том же результате. Для ФГОС рекомендуется `LLM_ANALYST_MODEL=deepseek-v4.1-flash-1017`.

Официальный PDF по-прежнему используется как резерв: если на странице нет
текста стандарта, воркер скачивает PDF и при необходимости включает OCR.
