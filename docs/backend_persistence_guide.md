# Подключение API к постоянному хранилищу

Сервер использует PostgreSQL через `api.PGStore`; память остаётся для изолированных тестов и SSE-демонстрации. Миграции ведутся отдельно, в ветке `feature/rustam/goose-migrations`, и в ветку бэкенда не переносились.

## Подготовка и запуск

Примените основные миграции до `20261110000000_run_stage.sql` включительно. Для поиска дополнительно нужен пакет `migrations_optional/vector` с отдельной таблицей версий Goose и установленным pgvector.

Задайте `DATABASE_URL`, `JWT_SECRET` и при необходимости `HTTP_ADDR` (по умолчанию `127.0.0.1:8080`), затем выполните `go run ./cmd/server`. Старый общий `API_TOKEN` больше не используется: запросы проходят JWT-проверку и проверку ролей Егора. Токен с ролью выдаётся существующим механизмом `auth.Issue`, секрет не хранится в коде.

## Данные и маршруты

- `PGStore` сохраняет и читает исследования, дерево, подтверждения и одобрение. Реализован метод `Save(*domain.Run)` для существующего оркестратора; этап, статус и время сохраняются в PostgreSQL.
- `PUT /api/v1/runs/{id}/tree` принимает плоский массив узлов. Доступен admin/teacher/rop. Валидатор проверяет цикл, сироту, пустое название, дубли у одного родителя, подтверждения, типы и уровни. Ответ 422 содержит `code`, `details` и при наличии `node_id`. Пустое исследование получает новое дерево, существующее дерево не заменяется (409). Отсутствующее исследование возвращает 404.
- Запись выполняется существующим `store.SaveTree` одной транзакцией через запросы sqlc. Ошибочная ссылка или ошибка фиксации не оставляет частичных узлов. SQL отсутствует в HTTP-хендлерах.
- `PGStore.Save` позволяет передать постоянное хранилище в `domain.Orchestrate`. Это ещё не означает, что POST создания исследования автоматически запускает настоящих агентов: их шаги и запуск должны быть подключены приложением.
- `GET /api/v1/runs/{id}/search?q=...&limit=5` возвращает `mode` (vector/bm25) и найденные фрагменты. Доступен admin/teacher/rop.
- `POST /api/v1/sources/{id}/index` доступен admin/teacher и создаёт фрагменты с векторами через Ollama. Нужны `OLLAMA_URL` (по умолчанию localhost:11434) и `OLLAMA_EMBED_MODEL` (по умолчанию nomic-embed-text). Требуется реальная модель с 768 измерениями. Фрагменты: до 800 символов, перекрытие 100 символов.

Индекс заменяется одной транзакцией после успешного получения всех векторов. Ошибка модели сохраняет прежний индекс. Если текст источника изменился во время получения векторов, операция отклоняется. Переиндексация заменяет фрагменты источника и удаляет векторы прежних моделей для этих фрагментов. При ошибке модели во время поиска используется BM25; это требует ранее созданных фрагментов, а не пустого источника.

## Проверки и границы

`INGEST_TEST_DATABASE_URL` должен указывать на отдельную тестовую базу со всеми миграциями, включая необязательные поисковые. `go test -count=1 ./...` проверяет бэкенд, транзакционный откат, 422, роли, экспорт, сохранение этапов, создание события и поиск с переключением.

Для реальной модели дополнительно задайте `OLLAMA_TEST_URL` и выполните `go test -v -count=1 ./internal/search -run TestНастоящаяOllamaДесятьЗапросов`. Проверяются десять запросов к тёплой модели на небольшом тестовом корпусе; холодный запуск и целевая нагрузка в этот норматив не входят. Без переменной этот тест пропускается.

Общий тест использует настоящие PostgreSQL, API и оркестратор, но тестовые шаги агентов. Полная пользовательская цепочка с настоящими агентами и n8n требует отдельной проверки. Авторизация ролей сохранена; разграничение владения отдельными исследованиями по пользователям в этой доработке не добавлялось.

Go-слой `internal/store` подключён из ветки БД. SQL и генерацию sqlc сопровождают там; при последующем объединении веток нужно сохранить одинаковую версию этого слоя. Устаревший `RunStatusStore` сохраняет только status; для этапов используйте `api.PGStore`.

Параметр strategy=hybrid включает объединение рангов vector и BM25 методом RRF (коэффициент 60). При недоступности модели возвращается BM25. Исходные оценки напрямую не складываются.
