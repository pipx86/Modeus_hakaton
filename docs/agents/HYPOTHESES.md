# Гипотезы AI-контура и целевые метрики

Документ фиксирует проверяемые гипотезы для интервьюера, аналитика и
синтезатора. Каждая гипотеза имеет метрику, целевое значение и способ
проверки. Гипотезы не являются обещаниями качества модели: это рамка
эксперимента.

## H1. Интервьюер покрывает все уровни деятельности

**Гипотеза.** Если вести интервью по плану role → function → task → action,
респондент называет достаточно конкретных задач и действий, чтобы построить
дерево без домысливания.

**Метрика.** Доля сессий, в которых за ≤ 7 вопросов получены ответы,
подтверждающие хотя бы одну сущность каждого уровня (`role`, `function`,
`task`, `action`).

**Цель.** ≥ 90% сессий на демо-наборе из 5 сценариев.
**Проверка.** `internal/agent/interviewer` — testdata-диалоги и
`TestSessionCoversAllLevels`.

## H2. Уточняющий вопрос повышает пригодность ответа

**Гипотеза.** Детектор неконкретных ответов (короткие/общие формулировки) и
один уточняющий вопрос уменьшают долю ответов, из которых аналитик не может
извлечь ни одной цитаты.

**Метрики.**
- `vague_answers_total` / `clarifications_asked_total`;
- доля неконкретных ответов, после уточнения ставших пригодными для
  извлечения сущности.

**Цель.** ≥ 80% уточнений превращают ответ в пригодный.
**Проверка.** `interviewer.IsVague`, диалоги с `expect.clarifications > 0`.

## H3. Каждая сущность подтверждена дословной цитатой

**Гипотеза.** Валидация «quote ∈ transcript» отсекает галлюцинации и делает
результат проверяемым вручную; издержки на ремонт приемлемы.

**Метрики.**
- `evidence_quote_mismatch_total` — ответы, отклонённые валидатором;
- `entities_with_verbatim_quote / entities_total` — в принятом результате
  должно быть 100%;
- `repair_success_after_quote_mismatch_total` — доля исправленных ответов.

**Цель.** 100% принятых сущностей имеют дословную цитату; после одного
ремонта исправляется ≥ 70% нарушений.
**Проверка.** `internal/agent/analyst` — `TestExtractRejectsNonVerbatimQuote`,
`TestExtractRepairsQuoteMismatch`.

## H4. Дедупликация не теряет evidence

**Гипотеза.** Дедупликация по нормализованному `(parent_id, title)` схлопывает
повторы, объединяя evidence, и не удаляет подтверждения.

**Метрика.** Число дубликатов до/после; ни одна уникальная цитата не потеряна.

**Цель.** 0 потерянных цитат; ≥ 90% точности схлопывания на размеченном
примере `demo_transcript.txt`.
**Проверка.** `analyst.DedupEntities`, `TestDedupMergesEvidence`.

## H5. Связь с таксономией не создаёт узлов без evidence

**Гипотеза.** Достраивание предков из таксономии (роль → функция) с
агрегацией evidence детей даёт связное дерево без необоснованных узлов.

**Метрика.** Число узлов без evidence в результате аналитика: 0.
**Цель.** 0; каждый сгенерированный предок несёт evidence минимум одного
потомка.
**Проверка.** `analyst.Taxonomy.Link`, `TestTaxonomyLinkAddsAncestorsWithEvidence`.

## H6. Приоритет источников разрешает конфликты предсказуемо

**Гипотеза.** Правило interview > standard > vacancy разрешает расхождения
названий/описаний так же, как это сделал бы методист, и конфликт не теряется.

**Метрики.**
- `conflicts_total` и доля разрешённых автоматически;
- согласие с ручной разметкой конфликтного набора.

**Цель.** ≥ 90% согласия на `synthesizer/testdata/conflict_sources.json`;
0 узлов без evidence; 100% конфликтов попадают в `conflicts` и `messages`.
**Проверка.** `internal/agent/synthesizer`, `TestSynthesizeConflictSources`.

## H7. Деградация LLM не останавливает интервью

**Гипотеза.** При 5xx/таймауте/circuit open интервью продолжается на
детерминированных вопросах, а run явно помечается `degraded`.

**Метрики.** Время ответа при недоступной модели (цель: ≤ 2× таймаута
провайдера, без зависаний); `degraded_runs_total`.

**Цель.** 0 зависаний, каждый degraded-run имеет явную ошибку в логе и
статус `degraded`.
**Проверка.** `internal/llm/circuitbreaker_test.go`,
`interviewer.TestModelErrorDoesNotBreakDialog`.
