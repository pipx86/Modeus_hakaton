# Пилот и обратная связь

Пилот включает три профессии: backend-разработчик, аналитик данных и DevOps-разработчик. Для backend-разработчика отдельно рассматриваются уровни junior, middle и senior. Профессии и уровни не следует автоматически считать взаимозаменяемыми.

Шаблон помогает подготовить карточки 27–29. Демонстрационные данные не являются согласованным эталоном. Выбор образовательной программы, участие специалиста и методиста и связанные с ними действия отложены до отдельного обсуждения.

## Ручной эталон

1. На основе действительных материалов подготовить черновик дерева «роль → функция → задача → действие» для каждой роли и уровня.
2. Для каждого ключевого узла записать цитату, источник и его идентификатор. Не приписывать источнику собственные выводы.
3. Отметить спорные узлы и объяснить причину неоднозначности.
4. Отметить, какие положения требуют внешней проверки. Согласование эталона будет выполнено после отдельного обсуждения.

В репозитории есть формат эталона и пример в `internal/agent/eval/testdata/reference/data-analyst.json`. Пример специально помечен демонстрационным и не подтверждает факты пилота.

## Проведение пилота

1. Создать исследование по выбранной профессии; для backend-разработчика явно указать уровень.
2. Убедиться, что использованы материалы из существующей базы; записать их состав и состояние.
3. Получить дерево, открыть основания нескольких узлов и проверить происхождение цитат.
4. Зафиксировать, какие шаги прошли, какие потребовали ручного вмешательства, ошибки и ссылки на исследование.

Интервью, сопоставление с конкретной программой и оценку человеком провести после отдельного обсуждения; до этого полный пилот нельзя считать завершённым.
