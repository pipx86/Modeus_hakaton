# Рабочие договорённости

- Миграции базы ведутся в ветке Рустама; не переносить их в ветку Егора без обсуждения.
- Недочёты совместного бэкенда можно исправлять в ветке Егора, коммитить и отправлять; после этого сообщать Рустаму об изменениях и проверках.
- Остальные действия с GitHub выполнять по отдельному запросу; перед изменениями проверять ветку и состояние файлов.
- Загрузчики требуют миграции базы из ветки Рустама. Секреты и токены задаются через окружение, их нельзя помещать в код или документацию.

- Подключён PGStore: сервер использует JWT_SECRET, данные API сохраняются в PostgreSQL. Перед запуском применить миграции до 20261112000000_run_type.sql включительно из ветки БД. Сами миграции в ветку бэкенда не переносились.

- Для hh.ru используется существующий общий access_token; не запрашивать новый и не отзывать текущий. Защищённая настройка хранится вне репозитория.

- После обновления ветки Егора построение предварительного дерева связано с реальными источниками и UUID из БД. Цитаты берутся из сохранённых вакансий; предложенные формулировки нуждаются в проверке человеком. Промежуточное состояние оркестратора пока не сохраняется, поэтому восстановление пересчитывает этапы.
- Загрузчик научных статей Crossref добавляет метаданные по явному запросу; автоматического выбора веса источников по профессии пока нет. Для нагрузочной проверки добавлена команда cmd/loadcheck.
- В совместном бэкенде реализованы ранее отсутствовавшие PostgreSQL-методы для списка исследований, создания и удаления источника, изменения узла и массового подтверждения. При удалении используемого источника возвращается 409. Для нового поля типа исследования нужна миграция 20261112000000_run_type.sql из ветки БД; сами миграции не переносились в бэкенд.
- События SSE подключены к успешному сохранению этапов оркестратора, в том числе при восстановлении; история пока хранится в памяти и теряется при перезапуске.
