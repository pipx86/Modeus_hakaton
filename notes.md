# Рабочие договорённости и техническое состояние

- Миграции БД ведутся в ветках Рустама. По отдельному запросу их объединили с ML/LLM-миграциями Ромы в интеграционной ветке `dev`; в feature-ветку Егора миграции не переносить без обсуждения.
- Если в совместном backend обнаружен недочёт, его можно исправить в актуальной backend-ветке, закоммитить и отправить; затем сообщить Рустаму, что сделано и как проверено.
- Остальные push и merge выполнять только по отдельному запросу. Перед изменениями проверять ветку и состояние файлов.
- Секреты и токены задаются через окружение и не включаются в код, документацию или Git.

## База данных

- PostgreSQL с pgvector 0.8.0 установлен на диске D. Проверки схемы и поиска выполнялись на отдельной тестовой базе.
- Миграции Goose включают основную схему, источники, дерево и подтверждения, снимки, SSE, справочники образования и ML/LLM-наблюдаемость.
- `evidence.ref_id` необязателен; при наличии ссылка на фрагмент сохраняется в снимке вместе с цитатой и сведениями об источнике.
- Для `run.completed` используется таблица `agent_messages`; backend worker доставляет события с HMAC-подписью и повторяет неудачные отправки.
- Unit-покрытие написанной вручную логики хранилища после объединения backend — 84,7%; запускатель находится в `scripts/Test-DatabaseUnitCoverage.ps1`. Интеграционные проверки PostgreSQL запускаются отдельно.
- Необязательные миграции pgvector применяются отдельно. Скрипт проверяет каталог PostgreSQL на D и просит пароль скрытым вводом; рабочая база этим слиянием не изменялась.

## Backend

- Сервер сохраняет исследования через PostgreSQL и использует JWT. Загрузчики вакансий, профстандартов, таксономий и образовательных программ требуют актуальной схемы БД.
- Для hh.ru используется общий действующий access token; новый токен не запрашивать и существующий не отзывать.
- Предварительное дерево строится из сохранённых источников. Формулировки, предложенные моделью, требуют проверки человеком; промежуточные этапы оркестратора сохраняются не полностью.
- Метаданные статей Crossref загружаются по явному запросу; автоматическая оценка веса источников пока не реализована.
- SSE-история хранится в PostgreSQL и восстанавливается после перезапуска; запись статуса исследования и SSE-события пока не атомарна.
- Снимки создаются по запросу, содержат дерево и подтверждения, а следующая версия получает новый номер.
- Idempotency-Key в текущем backend-хранилище действует в пределах процесса и не переживает его перезапуск.
- При удалении источника, используемого подтверждениями, API возвращает 409. Для нового подтверждения обязателен `node_id`; редактирование цитаты, источника или ссылки требует повторного одобрения.
- Локальный запуск всех unit-тестов backend выполняется командой `tests/unit/run.ps1`; тесты, требующие PostgreSQL и Ollama, запускаются отдельно.
