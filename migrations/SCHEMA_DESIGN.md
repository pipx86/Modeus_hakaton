# Данные для описания профессиональной деятельности

Это предварительная схема для обсуждения с командой. Она учитывает контракт проекта и задачи на загрузку источников.

## Данные для MVP

| Данные | Где хранятся | Назначение |
| --- | --- | --- |
| Исследование профессии | `runs` | Профессия, состояние, время, корень дерева, ошибка |
| Исходный материал | `sources` | Тип, название, содержимое, ссылка, внешний ID и состояние обработки |
| Дерево деятельности | `nodes` | Роль, функция, задача, действие и связь с родителем |
| Подтверждение | `evidence` | Цитата из источника для узла и признак подтверждения |
| Снимок результата | `snapshots` | Версия дерева на конкретный момент |
| Пользователи и роли | `users`, `roles` | Участники и принадлежность к роли |
| События агентов | `agent_messages` | Сообщения и подготовленное событие `run.completed` |
| Защита от повторного запроса | `idempotency_keys` | Ключ и сохранённый результат запроса |

`source_url` и `external_id` позволяют определить происхождение материала; `raw_payload` предназначен для исходных структурированных данных, например ответа API вакансий. Это поле необязательно. Внешние идентификаторы могут принадлежать разным поставщикам, поэтому глобальная уникальность здесь не задаётся. Индекс `(type, external_id)` ускоряет поиск, но не предотвращает дубликаты.

В текущем варианте у источника не более одного `run_id`; повторное использование одного источника несколькими исследованиями потребует связующей таблицы. Статус и этап исследования (`status` и `stage` в ветке оркестратора) необходимо согласовать: в текущей схеме триггер события наблюдает за `status`.

## Дальнейшая проработка

- Для вакансий: при реализации загрузки определить поставщика, правила дедупликации и необходимость отдельных полей работодателя, зарплаты, региона и даты публикации.
- Для образовательных программ: определить формат исходных данных и необходимость отдельных сущностей программы, дисциплины и компетенции.
- Для интервью: определить хранение респондента, согласия, стенограммы и времени интервью до загрузки реальных персональных данных.
- Для агентов: решить, какие сообщения и метрики модели сохранять, и нужны ли ограничения доступа и сроки хранения.
- Для `run.completed`: согласовать формат события и HMAC с получателем; отправщик в n8n пока не реализован.

## Одинаковая структура и данные

Миграции создают одинаковую структуру БД, но не синхронизируют записи между локальными базами. Общие демонстрационные данные должны поставляться отдельно и согласовываться командой.
