# Данные для описания профессиональной деятельности

Это предварительная схема для обсуждения с командой. Она учитывает контракт проекта и задачи на загрузку источников.

## Данные для MVP

| Данные | Где хранятся | Назначение |
| --- | --- | --- |
| Исследование профессии | `runs` | Профессия, состояние, время, корень дерева, ошибка |
| Исходный материал | `sources` | Тип, название, содержимое, ссылка, внешний ID и состояние обработки |
| Дерево деятельности | `nodes` | Роль, функция, задача, действие и связь с родителем |
| Подтверждение | `evidence` | Цитата, источник, необязательный `ref_id` фрагмента и признак подтверждения |
| Снимок результата | `snapshots` | Версия дерева на конкретный момент |
| Пользователи и роли | `users`, `roles` | Участники и принадлежность к роли |
| События агентов | `agent_messages` | Сообщения и подготовленное событие `run.completed` |
| Диалог чат-интервьюера | `run_chat_messages` | Реплики агента и респондента по порядку; история доступна после перезапуска backend |
| Защита от повторного запроса | `idempotency_keys` | Ключ и сохранённый результат запроса |

`source_url` и `external_id` позволяют определить происхождение материала; `raw_payload` предназначен для исходных структурированных данных, например ответа API вакансий. Это поле необязательно. Внешние идентификаторы могут принадлежать разным поставщикам. Индекс `(type, external_id)` ускоряет поиск, а отдельный уникальный индекс по `(provider, type, external_id)` предотвращает дубликаты, когда поставщик и внешний идентификатор заполнены. Для источников без поставщика автоматическое устранение дублей не гарантируется.

Таблица `run_sources` связывает один источник с несколькими исследованиями. Поле `sources.run_id` пока сохранено для совместимости со старым кодом: новая связь через него добавляется автоматически, но изменение или очистка поля не удаляет прежние связи. При создании подтверждения его источник автоматически связывается с исследованием узла. Удалить источник с подтверждениями нельзя.

Триггер события наблюдает за `runs.status`. Миграция `20261110000000_run_stage.sql` добавляет `stage` со значениями created/interview/analysis/synthesis/review/done/failed. Старые завершённые исследования получают соответствующий терминальный этап, прежние промежуточные этапы восстановить из одного status невозможно. Адаптер `RunStatusStore` по-прежнему пишет только общий статус; в бэкенде для сохранения этапа и статуса используется `api.PGStore`.

## Дальнейшая проработка

- Для вакансий: определить необходимость отдельных полей работодателя, зарплаты, региона и даты публикации. Уникальность при известных поставщике и внешнем ID уже предусмотрена. Загрузчик в ветке бэкенда ранее проверен с настоящим hh.ru; повторная проверка зависит от действующего токена.
- Для образовательных программ: таблицы программ, компетенций, KSA и связей с таксономиями уже добавлены. Поддержка дисциплин и разбор произвольных документов требуют дальнейшей проработки.
- Для интервью: определить хранение респондента, согласия, стенограммы и времени интервью до загрузки реальных персональных данных.
- Для агентов: решить, какие сообщения и метрики модели сохранять, и нужны ли ограничения доступа и сроки хранения.
- Для `run.completed`: в этой ветке подготовлены очередь и отдельный отправщик с HMAC-SHA256. Нужно настроить приёмник n8n, обеспечить запуск обработчика и проверить сквозную доставку в реальном окружении.

## Одинаковая структура и данные

Миграции создают одинаковую структуру БД, но не синхронизируют записи между локальными базами. Общие демонстрационные данные должны поставляться отдельно и согласовываться командой.

## Таксономии и образовательные программы

Миграция `20261109000006_education_taxonomies.sql` добавляет таблицы:

- `taxonomies` и `taxonomy_items` — справочник и его элементы, включая необязательного родителя в том же справочнике. Справочник может ссылаться на документ в `sources`.
- `education_programs` и `program_sources` — программы и их документы. Один документ может относиться к нескольким программам.
- `program_competencies` и `competency_ksa` — компетенции программы и их знания (`knowledge`), умения (`skill`) и навыки (`ability`).
- `competency_taxonomy_links` и `ksa_taxonomy_links` — связи компетенций и KSA с элементами справочников. Отсутствие связи означает, что запись ещё не сопоставлена.

Коды элементов справочника уникальны внутри справочника, а коды компетенций — внутри программы, если код указан. Дубли одинаковых связей запрещены. Источник, используемый программой или справочником, удалить нельзя. При удалении программы удаляются её компетенции, KSA и связи; элементы справочника, на которые имеются связи, защищены от удаления. Удаление справочника без внешних ссылок удаляет его элементы.

Эта схема описывает структуру и ограничения БД; загрузка и разбор документов выполняются приложением. В БД отсутствующий код допустим как NULL; повторный импорт без стабильного кода требует отдельных правил идентификации. Родитель элемента проверяется на принадлежность тому же справочнику и не может быть самим элементом; защита от более длинных циклов ещё необходима при импорте или редактировании. Связи KSA и таксономий сами по себе не подтверждают корректность данных — содержимое также нужно проверять в приложении. Откат миграции удаляет эти таблицы и их содержимое; перед откатом нужна резервная копия.
