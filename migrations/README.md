# Миграции базы данных

Миграции рассчитаны на PostgreSQL и выполняются инструментом Goose. Команды ниже запускаются из корня репозитория. `DATABASE_URL` должен указывать на отдельную тестовую базу PostgreSQL; не сохраняйте реальные пароли в репозитории.

В Git Bash:

```bash
export DATABASE_URL='postgres://USER:PASSWORD@localhost:5432/DBNAME?sslmode=disable'
goose -dir migrations postgres "$DATABASE_URL" up
goose -dir migrations postgres "$DATABASE_URL" status
```

Для проверки отката одной миграции и повторного применения на чистой тестовой базе:

```bash
goose -dir migrations postgres "$DATABASE_URL" down
goose -dir migrations postgres "$DATABASE_URL" up
goose -dir migrations postgres "$DATABASE_URL" up
```

`down` удаляет таблицы и данные, созданные последней миграцией. В установленной версии Goose эта команда откатывает одну миграцию; `down -1` не поддерживается. Второй `up` должен сообщить, что миграций для запуска нет.

## Решения, которые нужно согласовать

- Уникальный индекс `(parent_id, title)` запрещает одинаковые названия у одного ненулевого родителя. Корневые узлы с `parent_id IS NULL` могут иметь одинаковые названия, в том числе в разных исследованиях.
- При переходе `runs.status` в `done` триггер записывает событие `run.completed` в `agent_messages`. Использование этой таблицы как очереди — предварительное решение; его нужно согласовать с командой.
- Миграция не вычисляет HMAC и не отправляет событие в n8n. Для полной интеграции нужны отправщик, конфигурация секрета и адреса, согласованный формат подписи и проверка с получателем.
