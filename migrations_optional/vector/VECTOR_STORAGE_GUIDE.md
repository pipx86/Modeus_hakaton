# Необязательное хранилище векторного поиска

Этот пакет не входит в основные миграции. Он нужен для поиска похожих фрагментов источников и требует установленного расширения pgvector. Проверено на PostgreSQL 16 и pgvector 0.8.0. Сначала применяются основные миграции, затем этот пакет с отдельной таблицей версий:

```powershell
goose -dir migrations postgres $env:DATABASE_URL up
goose -table goose_vector_versions -dir migrations_optional/vector postgres $env:DATABASE_URL up
```

`source_fragments` хранит фрагмент источника и его порядковый номер; `fragment_embeddings` хранит вектор из 768 чисел и имя модели. Поле с вектором индексируется HNSW для косинусного расстояния. Для каждого запроса и записи нужно использовать одну и ту же модель и проверять её размерность на стороне приложения. Смешивать векторы разных моделей при вычислении сходства нельзя.

`find_relevant_fragments(run_id, вектор, модель, limit)` возвращает до 100 строк: `ref_id` — идентификатор фрагмента, `source_id` — источник, `quote` — текст фрагмента, `score` — косинусное сходство. Отбор выполняется только среди источников, связанных с исследованием. Возвращённый фрагмент не является подтверждённым фактом до проверки. При наличии многих моделей и фильтрации индекс приблизительного поиска может вернуть меньше результатов; качество и настройки нужно проверять на реальных данных.

Функция `find_fragments_bm25(run_id, текст, limit)` выполняет отдельное ранжирование BM25 без векторов по фрагментам, связанным с исследованием. Для нормализации используется встроенная русская конфигурация PostgreSQL; оценка BM25 не сопоставима напрямую с косинусным сходством. Подсчёт статистики пока выполняется по материалам исследования при запросе: производительность на большом корпусе не проверена. Метод `store.SearchFragments` принимает функцию построения вектора: при её ошибке или неверном результате он автоматически использует BM25 и возвращает режим поиска. Проверены оба режима на тестовой модели. Загрузка материалов и реальный клиент Ollama в этой ветке не реализованы; приложение должно подключить функцию модели и проверять права на исследование. Измерение в тесте охватывает только десять локальных запросов к базе со ста синтетическими фрагментами, не работу модели и не нагрузку в целевом окружении.

Интеграционный тест выполняется только в отдельной тестовой БД с обеими группами миграций:

```powershell
$env:VECTOR_TEST_DATABASE_URL = $env:DATABASE_URL
go test -v -count=1 ./internal/store/...
```

Откат пакета удаляет таблицы фрагментов и векторов; перед откатом в среде с данными необходима резервная копия. Расширение `vector` при откате не удаляется, поскольку его могут использовать другие компоненты. Нельзя откатывать базовую миграцию связей раньше, чем векторный пакет.
